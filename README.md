# 微信推文制作 Skill

把两个开源公众号内容项目整合成的一套自包含 skill：**选题 → 写作 → 审稿 → 排版 → 配图 → 发布**，
外加学习飞轮、数据复盘、多平台改写、业务资料库。

```
写一篇公众号文章   → 抓热点 → 选题 → 文章任务书 → 主张与证据 → 初稿 → 编辑审稿 → 成稿
完整制作           → 上面的成稿 + 配图 + 本地排版预览（仍不发布）
推到草稿箱         → 在上述基础上推送；不会因此自动生图
```

## 快速开始

```bash
cd wechat-article && bash install.sh
wxart doctor                      # 退出码 0 才继续
# 填 ~/.wxarticle/config.yaml 的 article_category / target_reader / default_author
```

然后对 agent 说「写一篇公众号文章」即可。不装依赖也能用纯提示词流程，
但排版、发布、生图、评分这些确定性命令需要运行依赖（见[安装与配置](docs/03-安装与配置.md)）。

## 设计原则

1. **prompt 负责判断，Python 负责确定性**——打分、转换、校验、接口调用走 `wxart` 命令；
   事实、观点与编辑判断由 Agent 做。
2. **一条链默认跑完正文**，说「交互模式」才在选题、框架、成稿三处停下确认。
3. **不可逆动作永远要门禁**：推送公众号、生成图片（产生费用）、覆盖已有文件。
4. **一篇文章一个任务目录**，两个引擎共用，可恢复、可追溯。
5. **正文封存后不可改写**，配图与排版只能产出新文件。
6. **不编造**：搜索失败可以继续写分析和经验判断，但不得把模型记忆包装成已核实的事实。

## 验证

```bash
bash wechat-article/tests/run.sh
```

56 项测试全绿：文档契约（触发边界、四道门禁、14 份阶段文档与内部链接、CLI 与文档同步、
无上游品牌残留）、工作区与状态解析（含「状态目录不能被当成项目标记」与断链自愈）、
两个排版引擎各出一份 HTML 并过门禁、容器栅栏拦得住跨引擎写法、任务生命周期与「未过审不许封存」。
