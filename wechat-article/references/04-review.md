# 审稿、定稿与改写循环

审稿是**编辑门禁**，不是挑错清单。发现可修的问题就**直接改稿并复审**，不改只提建议等于没审。只有编辑决定为 `pass`、五项达标、没有阻断问题、报告 `publishable=true` 时，才把终稿写成 `article.md`。最多两轮。

## 两种模式（自动识别）

| 模式 | 时机 | 检查重点 |
|---|---|---|
| **内容审** | 写作之后、排版之前 | 内容质量、写作规范、敏感词、AI 味、配图标记 |
| **终审** | 排版之后、发布之前 | 排版完整性、图片就位、发布要素齐全 |

**识别规则：任务目录里存在 `article.html` → 终审模式，否则 → 内容审模式。**

## 读取

- `{run_dir}/draft.md`（内容审）/ `{run_dir}/article.html`（终审）、`brief.yaml`、`claims.yaml`、`sources.yaml`（逐项回对的依据）。
- `{home}/config.yaml` 与 `{run_dir}/article.yaml`：**先 config 顶层（不含 `writing_model` / `image_model`），再叠本篇 `article.yaml`，同键本篇优先**；**只有 `embeds.related_articles` 做深度合并**，其余 `embeds` 以全局为准。审稿以合并结果为准：`review_output_format`、`custom_sensitive_words`、`forbidden_words`、`forbidden_title_phrases`、`target_reader`、`tone`、`image_density`、`title_max_length`、`summary_length`、`target_word_count`、`heading_density`、`original_attribution`、`custom_rules` 等。
- `{home}/writing-spec.md`、`{home}/presets/review-rules.yaml`、`wxart sources list --json`、`wxart run show`。

## 产出

`{run_dir}/assessment.yaml`（编辑判断临时输入，Agent 写）、`review-report.json`（`wxart content-eval` 生成）、`draft-stripped.md`（中间产物，可保留或删除）、`article.md`（**定稿**，第 5 步 BLOCKING 产物）。

## 命令

```bash
wxart sources list --json
wxart draft check {run_dir}/draft.md
wxart draft rewrite {run_dir}/draft.md --instruction "改成口语化" -o {run_dir}/draft.md
wxart draft strip-citations {run_dir}/draft.md -o {run_dir}/draft-stripped.md
wxart content-eval --draft {run_dir}/draft.md --final {run_dir}/article.md --assessment {run_dir}/assessment.yaml --output {run_dir}/review-report.json
wxart run update --patch '{"editorial":{"decision":"pass","pass_number":1,"publishable":true},"seo":{"title":"…","alt_titles":[],"digest":"…","tags":[],"quality_score":null}}'
wxart run step review completed
```

## 五步流程

1. **读约束**：按上面的合并顺序读出本篇全部阈值与词表。**先检查存在性，再做检查。**
2. **机器自检 + 逐项检查**：先跑 `wxart draft check`，再按清单人工过一遍。
3. **输出审稿结果**：按 `review_output_format` 输出，分三级 🔴 / 🟡 / 🟢。
4. **修改循环**：有 🔴 就改，改完**只重审 🔴 项**，直到无 🔴。
5. **⛔ BLOCKING 定稿**：剥离引用标注 → 追加文末 embed → 写 `article.md`。

**第 4 步完成不代表可以保存 `article.md`**，必须先走完第 5 步。**禁止**在未完成第 5 步「文末 embed」的情况下把稿件称为「已定稿」、写入 `article.md` 或进入排版。**禁止**用「用户没提」「节省时间」跳过文末占位符。

## 第 2 步：先跑机器自检

`wxart draft check {run_dir}/draft.md` 的判据与 [03-write.md](03-write.md) 的「自检」一节**完全同一套**：`>` 摘要、加粗密度与长度、裸名词、关键数字覆盖、带出处的金句恰好一处、`- **标签**：说明` 列表。

映射：脚本报的**硬性项 → 🔴**，**提醒项 → 🟡**。写作阶段本该跑过，但稿子可能是用户自己贴进来的、或中途手改过——**这里是最后一道能机器量的关口**。它还会把全文加粗串成一行打印出来；**那一串读起来像不像一份提要，仍要自己读一遍**——脚本量不了挑得对不对。

## 五项评分与门槛

每项 **1–5 分**：**准确**（核心事实有直接来源；事实、推断、意见分得开；结论没有超出证据边界）；**观点**（核心判断明确，说明新增价值、适用范围和最强反方，不重复常识充数）；**有用**（真正回答目标读者的问题，给出可执行行动、决策条件或可迁移的理解框架）；**合声**（符合账号语气但不被人格模板绑架；个人经历只来自本次用户材料；没有挪用范文）；**好读**（开头迅速进入问题，各节各有任务，论证连贯，标题准确，语言直接且无重复）。

**交付门槛（三条同时满足）**：平均分 **≥4**、单项 **≥3**、**无阻断问题**。

## 三类阻断问题

**任一类出现都不能交付**，必须改掉或删掉：① **事实类**——核心具体事实没有来源，或来源不支持正文说法；把推断写成确定事实；结论超出证据边界。② **材料类**——编造作者亲历、朋友、同事、采访、对话、场景、时间地点或身份。③ **交付类**——没有给目标读者明确的结论、行动或判断方法；核心论点与证据脱节，用漂亮结构掩盖答非所问。

**核对方法**：把正文中的具体数字、日期、引述、研究结论和时效性事实**逐项**对到 `claims.yaml` 与 `sources.yaml`；来源不支持时优先补查，查不到就删除、缩小或改成明确的推断，**不能用模型记忆补洞**。再检查所有第一人称事件、朋友同事、采访、对话、时间地点和感官细节——它们必须来自本次任务明确记录的用户材料。

## 三类编辑决定

| 决定 | 条件 | 动作 |
|---|---|---|
| `pass` | 无阻断问题，五项达到交付门槛 | 进第 5 步 |
| `revise` | 问题能在现有材料内修正 | **直接改稿**并重新执行 1–3，**不得只写建议** |
| `needs_input` | **仅限**用户明确要求写其个人故事，而关键材料缺失且无法安全换框架 | 说明缺什么 |

其它情况一律自动缩小主张或换框架，不用 `needs_input`。**最多两轮。** 第二轮仍未达标时**不得假装通过**：删掉不可靠内容、缩小承诺，交付能被证据支持的版本。

## 第 2 步：完整检查清单

**标题**：字数不超过 `title_max_length`（未配置时按 25 字）；不含 `forbidden_title_phrases` 中的套路（浅谈 / 万字长文 / 建议收藏 / 震惊 / 不转不是中国人 / 夸张承诺 / 学术体）；与正文内容一致、不做标题党（数字、反直觉、痛点写法有正文支持）；有吸引力。

**摘要**：字数在 `summary_length` 范围内（未配置时用 80–128 字并注明用了兜底值）；能概括文章核心价值、不重复标题、不制造正文没有回答的悬念；与正文内容一致；不是正文第一段的复制；**与正文首个 `>` 导语不是同一句话**（实测 7 篇逐字相同——摘要在后台列表出现一次、导语在正文开头再出现一次，读者等于同一段读两遍）。

**正文内容**：不含 `custom_sensitive_words` 和 `forbidden_words`；无明显错别字和语病；事实与数据有出处（对 `claims.yaml` / `sources.yaml`）；原创 / 转载标注按 `original_attribution` 处理（它是发布元数据，**不进正文**）；开头 2–3 句有吸引力，不用「随着…的发展」「在当今这个时代」这类万能套话；无新闻电头（「XX 发自 北京」「XX 报道」「本报记者」）。

**写作规范合规**（对照 `{home}/writing-spec.md`；不存在则**整个维度跳过**，不报错）：用词规范（标点、中英文间距、数字格式）；句式偏好（句长、主动语态、无套话）；段落规范（段长、核心观点位置）；禁止事项（无夸张承诺、无未验证数据——AI 味单列，见下）；品牌调性与规范中的调性描述一致。**AI 味自检**单列在下一节，**默认只诊断**，一律折算 🟡，不 blocking、不影响定稿。

**配图标记**：封面标记存在（`![封面：…](placeholder)`）且放在标题 `#` 行之前；配图数量与 `image_density` 匹配（未配置时默认每节一图）；每个标记的描述清晰、有具体内容（不是「配图」「示意图」）；类型名只在 `封面` / `实证` / `信息图` / `氛围` 四者内，不是字面「类型」，冒号后不等于类型名；标记独占一行、前后留空行、用 `![]()` 而非 `[]()`；实证类标注了需用户提供，信息图冒号后含具体数据点或维度；`image_source=user` 时无 `placeholder`，路径真实存在。

**结构**：小标题密度符合 `heading_density`；结尾有力（总结 / 金句 / 行动号召），交互型收尾是自然句子，**没有**「互动话题」「互动时间」这类标题或加粗标签；文末引导区块按 `closing_block` 处理；配置了 `target_word_count` 时篇幅在范围内；三项以上并列写成了 `- **标签**：说明` 列表，没有压进长段落。

**终审额外项**：`article.html` 存在且内容完整、无乱码或格式异常；`imgs/` 目录存在，所有 `placeholder` 已替换为实际路径且文件真实存在；封面在**文章目录下**（`cover.png` / `.jpg` / `.jpeg` / `.webp`）——**不在 `imgs/` 里**；标题、摘要、作者已最终确认，正文无草稿标记或未替换占位符；评论 / 仅粉丝可评等设置已确认。

**自定义规则**：`{home}/presets/review-rules.yaml` 的规则**排在标准项之后**执行：

```yaml
custom_rules:
  - {name: 品牌名称规范, check: 正文中「XX公司」必须使用全称，不能简写, level: 必须}
  - {name: 数据来源, check: 所有引用的数据必须标注来源和日期, level: 必须}
  - {name: CTA 检查, check: 文末必须包含明确的行动号召, level: 建议}
```

`level: 必须` 命中判 🔴（进修改循环），`level: 建议` 判 🟡。

## 敏感词与禁用词机制

| 配置键 | 作用 | 命中判级 |
|---|---|---|
| `custom_sensitive_words` | 本篇 / 本号的敏感词表 | 🔴 |
| `forbidden_words` | 禁用词 | 🔴 |
| `forbidden_title_phrases` | 标题禁用套路 | 🔴 |
| `custom_rules[].level: 必须` | 自定义规则，必须 | 🔴 |
| `custom_rules[].level: 建议` | 自定义规则，建议 | 🟡 |

没有配置的词表就不检查，**不要凭个人判断新增敏感词**；疑似合规风险（政治、医疗、金融承诺、绝对化用语）单独在审稿说明里列为提示，不要与词表检查混在一起报。

## 阈值缺失的兜底

约束缺失时**不要中断审稿**：

| 缺什么 | 怎么办 |
|---|---|
| `target_reader` / `tone` 等内容向约束 | 说明「部分维度无法按本篇约束对齐」，建议补全 `config.yaml` / `article.yaml`，其余维度照审 |
| `writing-spec.md` 不存在 | 跳过「写作规范合规」整个维度 |
| `presets/review-rules.yaml` 不存在 | 只执行内置清单 |
| `title_max_length` / `summary_length` 缺失 | 用微信侧硬限兜底：**摘要 ≤128 字**，标题按 25 字；**并在输出里注明用的是兜底值** |

## AI 味诊断

**立场**：AI 味的本质是「太完美」——太顺、太均匀、没有取舍。诊断的目的是让作者看清自己的文字哪里在偷懒，**不是**教 AI 伪装成人。**发现 AI 味只提示、不强制改，更不因为它阻断定稿。** 审稿只指出「这里读起来像 AI、原因是什么、可以往哪个方向调」，**不擅自代改**。

**信号强度（诊断级）**：**强信号**＝几乎只有 AI 才这么写，人类作者极少自然产出；**中信号**＝AI 高频，但人类在赶稿或偷懒时也会写出来；**弱信号**＝看体裁和语境，单独出现往往不是问题，扎堆才算。

⚠️ 「强 / 中 / 弱」只表示**像不像 AI**，与审稿总评的 🔴必须 / 🟡建议 / 🟢通过（**行动级**）是两套体系。**无论强信号还是弱信号，AI 味命中一律折算为总评里的 🟡。** 不要在 AI 味诊断里写 🔴/🟡/🟢，也不要把「强信号」当成「必须改」。

**15 条指纹库**——按正文顺序**逐处**指出，引用原句，别按类型归类堆在一起：

| # | 指纹 | 公众号里的典型样子 | 信号 |
|---|---|---|---|
| 1 | 工整三段式排比 | 「它让你更专注，让你更高效，让你更从容。」每节都来一组对仗，整齐得像 PPT | 中 |
| 2 | 「不是 X，而是 Y」句式滥用 | 「这不是工具，而是伙伴。」「重要的不是速度，而是方向。」 | 强 |
| 3 | 面面俱到、没有取舍 | 利弊、前提、例外、适用人群全讲一遍，什么都对，什么都不得罪 | 强 |
| 4 | 反复让步、两头讨好 | 「当然，这并不是说……」「诚然，也有人认为……」「不可否认……」 | 中 |
| 5 | 命名仪式感 | 「我把这套方法称为『黄金三角法则』。」给普通做法硬安唬人的名字再郑重解释 | 中 |
| 6 | 情绪曲线太平滑 | 从头到尾一个温度，均匀的「温暖」「治愈」「赋能」，没有激动、烦躁、犹豫、泄气 | 中 |
| 7 | 「你值得 / 愿你」式祝福收尾 | 「愿你在喧嚣中找到自己的节奏。」正确而空洞，谁都适用、谁都记不住 | 强 |
| 8 | 翻译腔 | 「值得注意的是」「在某种程度上」「众所周知」「让我们来看看」，很长的前置定语从句 | 中 |
| 9 | 万能套话开头 | 「随着 AI 技术的发展」「在当今这个时代」「在快节奏的现代生活中」 | 强 |
| 10 | 强行拔高升华 | 讲快捷键的小技巧，结尾扯到「人生」「时代」「意义」「成长」 | 中 |
| 11 | 模板化假故事 | 「我有个朋友……」「记得有一次……」开头，但细节全是空的 | 中 |
| 12 | 总分总八股 + 「总而言之」 | 开头预告「本文将从三个方面」，中间整齐分点，结尾「综上所述」收口 | 中 |
| 13 | 过度规整的标点与节奏 | 句子长度高度均匀，破折号、分号用得很书面，没有短促的口语断句、省略 | 弱 |
| 14 | 形容词 / 副词通货膨胀 | 「极其重要」「无比关键」「真正意义上的」「彻头彻尾地」 | 弱 |
| 15 | 概念名词扎堆、缺具体 | 满屏「赋能、闭环、抓手、底层逻辑、认知升级」，通篇没有一个能复现的步骤或真实数字 | 中 |

**防误判阈值（别冤枉正常写作）**——指纹本身不等于罪证，**关键看密度和语境**。下面这些情况**不要**判命中：

- **「不是 X 是 Y」**：**800 字内出现 ≥3 次**才算命中；单次、两次是正常修辞，放过。
- **排比 / 对仗**：单处是好文笔，**只有当几乎每节都在排比**时才算命中。
- **让步句（「当然」「诚然」）**：观点确实有争议、需要交代边界时是负责任，不算；只有**每个论点前都垫**才算。
- **故事**：有具体细节（时间、地点、对话、尴尬、数字）的故事不算「模板化假故事」，哪怕开头也是「我有个朋友」。
- **升华**：文章主题本就关于价值观 / 人生的，结尾谈意义是切题，不算「强行拔高」。
- **开头**：具体的痛点提问（「你是不是也囤了几百个 Prompt」）不是万能套话。
- **术语**：真实技术术语（如「渐进式披露」「最小闭环」）不是「硬安名字」。
- **概念词**：有具体步骤、命令、文件名或数字支撑的概念词不算「概念扎堆」。
- 拿不准时**宁可不报**。文章干净就直接说干净，不强行命中。

**与 writing-spec 的豁免边界**——AI 味自检是 `writing-spec.md` 的**补充诊断层**，两者分工、**不重复扣分**：

- writing-spec 已明令禁止的套话（「随着 AI 发展」「总而言之」）由写作规范维度负责；AI 味维度可以指出，但**不要在两个维度各扣一次**。
- **writing-spec 鼓励的写法一律不算 AI 味**，包括：用「你 / 大家」直接对话、用生活化类比解释概念、短句短段、口语化、**固定互动收尾**（「点赞、在看、加星标……下期见」）。这些是规范要求的「人味」，**不得反过来当 AI 味命中**。
- 一句话原则：writing-spec 管「该不该这么写」，AI 味维度管「读起来像不像 AI」；只有当某处**既不被 writing-spec 鼓励、又落在指纹库里**时，才算命中。

**体裁宽严**：**公众号长文 / 干货**标准最严，最该有作者的取舍和观点，八股结构、面面俱到、强行升华都更刺眼；**短文案 / 朋友圈 / 推送语**篇幅短，排比和工整反而可能是设计，放宽，重点看有没有套话开头和空洞祝福；**标题**单独看「不是 X 是 Y」「你值得」很常见，**不按正文标准扣**，只在确实千篇一律时提示。**诊断前先判体裁，再按对应宽严执行。**

**校准要点**（诊断风格漂移时用来回头校准）：**首要命中应是「工整对仗 / 金句扎堆」**——这是推广类干货最典型的 AI 节奏，抓不到它就是报得太松；系列文跨篇复用的统一口号、语境相关时属弱信号，放过。**该放过的**：阈值内的「不是 X 是 Y」、具体痛点提问、真实术语、有步骤支撑的概念词、固定互动收尾、口语对话、生活化类比、与主题相关的轻度拔高。**全部命中折算 🟡、不 blocking**——AI 味不进强制修改循环、不阻断定稿。

## 第 3 步：输出格式

按 `review_output_format` 选一套：

**分块详细**（默认）：按维度分块，逐项 `- [x]` / `- [ ]` + 修改建议，每块末尾给 `🔴 修改建议：…` 或 `🟡 建议修改：…`；结尾一张汇总表（🔴 / 🟡 / 🟢 数量）+「下一步：修正 🔴 项后重审 → 通过后保存为 article.md」。

**简要清单**：一张表格，一行一项（检查项 / 结果 / 说明），下面两行列出 `🔴 必须修改` 与 `🟡 建议修改` 的具体条目。

**终审**：表格（排版完整 / 封面图 / 正文配图 / 占位符 / 标题确认 / 摘要确认 / 评论设置），结尾一行 `**结论**：✅ 可以发布` 或具体缺口。

**修改循环（重审）**：**只显示之前标记为 🔴 的项**，每项 `- [x] … ✅ → 已修正`，结尾 `**结论**：🔴 项已全部消除，可保存为定稿`。

三级判定：🔴 **必须修改**（不改不能过：敏感词、严重错别字、缺封面、机器自检硬性项、自定义 `level: 必须` 命中）；🟡 **建议修改**（用词优化、段落调整、AI 味、机器自检提醒项、`level: 建议` 命中）；🟢 **通过**。

## 工具分数

`wxart score {run_dir}/draft.md --verbose` 输出 11 项机械检测；`--json --tier3 0.7` 可附加 Agent 打分（0–1，权重 T1 50% / T2 30% / T3 20%）。它只帮助定位套话、句式过齐和段落节奏风险，**不设机械及格线**，**不参与放行或否决判断**，也不要为了提分反复重写。`wxart content-eval` 是**确定性汇总器**，不是评分器：它只把你写好的 `assessment.yaml` 与初稿 → 终稿的文本差异算成 JSON。**工具分数不参与放行判断**——放行只由五项评分、阻断项与 `publishable` 决定。

## 第 5 步：剥离引用标注 → 文末 embed → 写定稿 ⛔ BLOCKING

全部 🔴 消除后：**① 展示最终审稿结果，等用户确认**（交互模式下）。**② 剥离引用标注**：`wxart draft strip-citations {run_dir}/draft.md -o {run_dir}/draft-stripped.md`——纯本地正则剥掉正文里所有 `（资料路径：…）`（写作阶段为事实溯源强制注入，发布版必须去除，以免泄露内部产品目录路径）。**禁止用 `sed` 或肉眼撕替代该脚本**——历史上多次「撕一遍漏一条」。**③ 文末 `embeds`**：在写入 `article.md` **之前**，按合并后的配置在 `draft-stripped.md` 的**正文末尾**追加占位符。

   | 占位符 | 何时写入 | 配置对齐 |
   |---|---|---|
   | `{embed:profile:…}` | `embeds.profiles` 有至少一条非空 `nickname` | 每条有效项一行，`…` = 该项 `nickname` |
   | `{embed:miniprogram:…}` | `embeds.miniprograms` 有至少一条非空 `title` | 每条有效项一行，`…` = `title` |
   | `{embed:miniprogram_card:…}` | `embeds.miniprogram_cards` 有至少一条非空 `title` | 每条有效项一行，`…` = `title` |
   | `{embed:link:…}` | `embeds.related_articles.manual` 有有效项 | `…` = 该项 `name`；**至多 3 条** |

   **规则**：**至多 3 条 `{embed:link:…}`**，超过时只保留与本文主题最相关的或按列表顺序取前 3；占位符必须与**合并后可解析的配置一致**，否则排版阶段会失败；`profiles` / `miniprograms` / `miniprogram_cards` 列表未配置、为空、或无非空关键字段 → **不追加**该类占位符，无需处理；`manual` 缺失或为空 → **本环节不自动补齐**（审稿保持纯本地、无网络、无凭证），首选请用户把已发表文章的 `name` + `url` 写进本篇 `article.yaml` 的 `embeds.related_articles.manual`（至多 3 条），或进发布环节由 `wxart getdraft` 的 `published-fields` 补齐；用户声明跳过往期推荐 → **不伪造** `manual`，在审稿说明里注明「本篇跳过往期推荐」，`{embed:link:…}` 省略；**全空时必须显式标注**「文末 embed：无配置，已跳过」，**不得静默跳过**——静默跳过之后没人能分辨是「配置为空」还是「这一步漏了」；`embeds.related_articles` 是**本篇唯一深度合并**的 embeds 字段，名片与小程序仍以全局为准，不要在本篇写。

4. 把**已剥离引用标注且含文末 embed**（或已按规则省略并记入审稿说明）的稿件保存为 **`article.md`（定稿）**。

**未完成第 3 小步不得保存定稿、不得排版。**

## 落盘：`assessment.yaml` → `review-report.json`

先写 `{run_dir}/assessment.yaml`：

```yaml
decision: pass          # pass / revise / needs_input
pass_number: 1          # 1 或 2
dimensions: {accuracy: 4, viewpoint: 4, usefulness: 4, voice: 4, readability: 4}
blockers: []
major_issues: []
notes: ""
```

字段校验（不合法则脚本退出码 2 并打印 `Error: …`）：`decision` ∈ `pass` / `revise` / `needs_input`；`pass_number` ∈ `1` / `2`；`dimensions` 必须含五项 `accuracy` / `viewpoint` / `usefulness` / `voice` / `readability`，各为 **1–5** 的数值（布尔不算）；`blockers` 与 `major_issues` 必须是列表；`--draft` 与 `--final` 两个文件都必须非空。再生成 `{run_dir}/review-report.json`：

```bash
wxart content-eval --draft {run_dir}/draft.md --final {run_dir}/article.md \
  --assessment {run_dir}/assessment.yaml --output {run_dir}/review-report.json
```

**报告字段全列**：`version`（固定 `1`）、`decision`、`pass_number`、`publishable`、`dimensions`（五项浮点）、`dimension_average`（保留 2 位）、`blockers`、`major_issues`（最多列 5 个，按影响排序）、`notes`、`draft_chars`、`final_chars`、`edit_ratio`、`structure_changed`。

**`publishable` 的计算式（确定性）**：`publishable = (decision == "pass") and (blockers 为空) and (min(五项分数) >= 3) and (dimension_average >= 4)`。因此：写 `article.md` **之前**先自检 `assessment.yaml` 是否满足这个式子；它不满足时 `publishable` 必为 `false`，此时**不要**写 `article.md`，回到修改循环。

`edit_ratio = round(1 − SequenceMatcher(draft, final).ratio(), 4)`，是初稿到成稿的实际变化幅度，会把剥离引用标注与追加 embed 的文本变化一并计入——不设单篇硬门槛，只用来观察初稿稳定性。`structure_changed`＝`^##\s+(.+)$`（MULTILINE）提取的标题序列是否不同；为 `true` 时在审稿说明里写一句调了什么。

**更新任务并完成**：

```bash
wxart run update --patch '{"editorial":{"decision":"pass","pass_number":1,"publishable":true},"seo":{"title":"…","alt_titles":[],"digest":"…","tags":[],"quality_score":null},"provenance":{"verified_sources":0,"unverified_sources":0}}'
wxart run step review completed
```

`seo.alt_titles` 给两个角度不同但同样准确的备选标题；`tags` 给 3–5 个能准确描述文章的标签，不为热点流量加入正文未覆盖的词。**只有 `publishable=true` 才能完成审稿。** 封存时 `wxart run finish` 会再校验一次：`article.md` 非空、`editorial.decision=pass` 且 `publishable=true`。自检报告用自然语言，最多列 5 个按影响排序的问题，并说明已经怎样修正。没有硬伤就直说正文可以交付。

## 分支

| 情况 | 处理 |
|---|---|
| `article.html` 存在 | 走**终审**模式，在内容审基础上加排版 / 图片 / 发布要素三项 |
| 稿子由用户直接贴入 | 仍跑 `wxart draft check`，再走完整清单 |
| 约束缺失 | 按「阈值缺失的兜底」表逐项降级，**不中断审稿** |
| 有 🔴 项 | 进修改循环：发现问题 → 展示结果 → 修改 → 重新检查 → 直到无 🔴 |
| 修改方式 | Agent 直接改 `draft.md` / 用户手改后说「改好了」/ `wxart draft rewrite` |
| 每轮重审范围 | **只重审被标为 🔴 的项**，不必全量重审 |
| 两轮后仍不达标 | 删不可靠内容、缩小承诺，交付能被证据支持的版本；不得贴「可交付」标签 |
| 用户只想要挑错清单 | 第 3 步输出后停下，**但不得写入 `article.md`**——它一旦存在，下游会当成已定稿 |
| 用户书面声明不要嵌入元素 | 在审稿说明中写明「用户声明跳过 embed」，并确认不是误操作；**唯一例外** |
| `manual` 为空且用户要往期推荐 | 请用户给 `name` + `url` 写进本篇 `article.yaml`，或留到发布环节补齐 |
| 正文仍有 `placeholder` | 状态必须报「配图未完成」，不得宣布全流程完成 |
