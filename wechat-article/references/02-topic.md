# 选题、标题与摘要

选题决定这篇文章写给谁、值不值得写。这一步只产出「写什么」，不产出正文。
用户已经给了具体选题 → 直接落盘并跳到标题与摘要；其余情况按本文走完调研 → 打分 → 选题卡 → 落盘。

## 读取

- `{home}/config.yaml`：`article_category`、`target_reader`、`default_author`、`topic_direction`、
  `update_frequency`、`blacklist`、`forbidden_title_phrases`、`title_max_length`、`summary_length`、
  `default_title_style` / `custom_title_style`。`wxart env` 打印实际生效的是哪一份配置。
- `{home}/style.yaml`：`topics`、`content_style`、`target_audience`、`blacklist`。不存在就问
  「你的公众号主要写哪几个方向？」，用当轮回答临时代替 `topics`，并提示可用 `wxart init` 补全。
- `{home}/history.yaml`：近 30 天的 `topic_keywords` 与 `stats`（有则用，没有只做去重）。
- 当前任务：`wxart run show`。**不要直接读 `state.yaml`**。

## 产出

- `state.yaml` 的 `topic.title`、`topic.keywords`、`topic.source`、`topic.framework_hint`——唯一落盘位置，
  只通过 `wxart run update --patch` 写。交互模式下额外在对话里输出选题卡与调研摘要；
  模式 D 额外落 `{home}/series/<系列slug>/plan.md`。

## 入口：先归类 A/B/C/D

**在联网调研之前**先归类；用户这条消息已说清就一句话确认，不重复盘问。**两类输入**：用户**已给方向**（A/B）→ 全程围绕该方向收敛，不另起话题；用户**没给方向**（C）→ 用 `article_category` + `topic_direction` 代方向；**系列/专栏**（D）→ 按系列走。

| 模式 | 判据 | 本轮做什么 |
|---|---|---|
| A 明确选题 | 给了具体话题 | 不生成 10 题；走模式 A 的三轮调研，给 3–4 个切入角度 |
| B 有方向 | 给了领域，没给题目 | 调研热点与趋势，出 10 个选题 |
| C 无方向 | 只说「找几个选题」 | 用 `article_category` + `topic_direction` 代方向，出 10 个选题 |
| D 系列策划 | 提到系列 / 专栏 / 连载 | 出系列总线 + 每篇选题，落 `plan.md` |

**禁止**在用户仍处于「只说找选题、没说领域或偏好」的模糊状态时开始联网调研——搜出来没有收敛方向。
选题涉及用户自身业务（产品 / 软件 / 服务）时，先 `ls {home}/products/` 并读相关产品根下的 `*.md`，
从中找契合自家业务的角度。**禁止**把业务资料里没有的能力写进选题卡当卖点。

## 硬规则：先查账号三键

生成任何选题之前，确认 `article_category`、`target_reader`、`default_author` 三项 **trim 后均非空**。
缺失就**逐项询问用户**，取得当轮明确答复后**写回 `{home}/config.yaml`**。
**禁止**从 `article.yaml`、其它草稿或仓库文件静默抄录推断；**禁止**只在对话里确认而不落盘。

## 调研顺序（固定四步）

**第 1 步 · 热点**：`wxart hotspots --limit 30`。输出 JSON 列表，每条含 `title` / `source`
（微博 / 今日头条 / 百度）/ `hot`（热度值）/ `url` / `description`。三个平台分别抓，某一家失败只打
`[warn]` 不影响其余。**降级**：命令整体报错 → 改用 `web_search "今日热点 {topics 第一个垂类}"`；
单平台失败不要重试超过一次。

**第 2 步 · 垂类高频需求**：对 `topics` 的**前 1–2 个垂类词各搜一次**近一周的公众号文章：

```bash
wxart search-articles "{垂类词}" -n 15 -t 2
```

- `-n` 返回条数（默认 10，最大 50）；`-t` 时间过滤 `1`=一天内 `2`=一周内 `3`=一月内 `4`=一年内
  （客户端过滤，最多扫 5 页）；`-r` 逐条解析 `mp.weixin.qq.com` 直链（每条额外请求）；`-o` 另存 JSON。
- 每条字段：`title` / `url` / `summary` / `datetime` / `source`（账号名）。
- **三条必须记住的限制**：① **结果不带阅读量**，只能说明同题出现频率，**不能**声称某篇是「爆款」；
  ② 搜狗有反爬限流，属常态；③ **降级**：报错或结果为空 → 跳过本步、不阻断，选题构成退回默认（份额还给热点）。

**第 3 步 · SEO**：`wxart seo --json {关键词}`。输出每条含 `keyword`、`seo_score`（0–10，
= 百度分 + 360 分合并）、`baidu_score`、`so360_score`、`so360_suggestions`、`related_keywords`（前 10 个）。
选题卡里的 SEO 友好度**必须引用这份数据**，不要靠猜。
**降级**：脚本报错 → 由你判断关键词价值，并在选题卡里注明「SEO 数据不可用」。

**第 4 步 · 历史**：读 `{home}/history.yaml`，取近 30 天的 `topic_keywords` 做去重扣分（见下）。
有 `stats`（阅读量、分享量）且样本 **≥5 篇**时，额外做效果闭环：

- 统计每种 `framework` 的平均阅读量与分享率 → 表现好的框架在推荐时 **+1~2 分**。
- 统计每种 `enhance_strategy` 的平均表现 → 供 [03-write.md](03-write.md) 选增强策略时参考。
- 分析高表现文章的标题特征（数字型 / 反直觉 / 痛点 / 提问）→ 拟标题时参考。
- 实际高表现类型与 `content_style` 设置不符 → 在调研摘要末尾提示一句。

`stats` 不足 5 篇就跳过效果分析，只做去重。

## 10 个选题的构成

| 份额 | 类型 | 来源 |
|---|---|---|
| 5–6 个 | 热点 | 第 1 步，按下面三维打分 |
| 2–3 个 | 高频需求 | 第 2 步，按同题密度打分；无产出时份额还给热点 |
| 2–3 个 | 常青 | 从 `topics` 生成长尾（教程 / 方法论 / 经验总结 / 工具推荐） |

数量受 `update_frequency` 影响：周更约 3–5 个，日更略多，月更略少；无配置时按上表。
**不足 10 个时**：热点相关度 ≥5 的不足额定份额 → 用高频需求或常青补足；补足后仍不足 10 个 →
直说「今天热点跟你的领域匹配度不高」，输出能找到的，并请用户自己给选题。

## 三维打分算法

对每个选题的三个维度各打 1–10 分。

**热度分（权重 30%）**：热搜前 10 → 8–10 分；10–30 名 → 5–7 分；30 名之后 → 1–4 分；
多个平台同时出现 → **+2 分**，封顶 10。

**相关度分（权重 40%）**：直接命中 `topics` 列表 → 8–10 分；间接相关（做「AI」，热点是「芯片出口管制」）
→ 5–7 分；勉强能扯上关系 → 3–4 分；完全无关 → 0 分。
命中 `blacklist` 的词汇或话题 → **直接判 0，整个选题淘汰**。

**切入价值分（权重 30%）**：有明确的反直觉点或信息差 → 8–10 分；有争议、有正反两面可讨论 → 6–7 分；
纯资讯、搬运即可 → 3–4 分；太复杂不适合 2000 字展开、或太浅没东西可写 → 1–2 分。

**`content_style` 加成**（加在切入价值上，加成后封顶 10）

| `content_style` | 加分条件 | 加分 |
|---|---|---|
| 干货 | 能输出方法论 / 工具 / 教程 | +2 |
| 故事 | 有人物、有情节、有转折 | +2 |
| 情绪 | 能引发共鸣、愤怒、感动 | +2 |
| 热点 | 正在热搜前 10 | +2 |
| 测评 | 涉及产品 / 工具 / 方案对比 | +2 |

**综合评分**：`总分 = 热度 × 0.3 + 相关度 × 0.4 + 切入价值(含加成) × 0.3`

**历史去重扣分**（在总分上扣，扣完再排序）：核心关键词在**最近 7 天**已出现 → **−3**，
标注「⚠️ 近期已覆盖类似话题」；在 **7–30 天**内出现 → **−1**，标注「ℹ️ 月内有相关文章」；
超过 30 天 → 不扣分。

**常青选题**：热度分**固定为 5**，相关度与切入价值正常评分，标注 `🌲 常青`，与热点混排。

**选型原则**：不要只挑热度最高的。热度 6 分但相关度 10 分的选题，通常比热度 10 分但相关度 3 分的更好。

## 高频需求选题：同题密度与逻辑拆解

用**同题密度**顶替热度项：同一选题 / 角度被 **≥5 个不同账号**写过 → 8–10 分（强验证需求）；
**3–4 个账号** → 6–7 分；**1–2 个账号** → 3–5 分（可能是孤例，谨慎）；
发布时间越集中越新（如全在 48h 内）→ **+1~2 分**，封顶 10。

**每个高频需求选题必须附一段「逻辑拆解」**：**需求本质**（这批文章满足了读者什么：情绪宣泄 /
信息差 / 身份认同 / 实操焦虑）；**形式逻辑**（共同的标题公式、结构钩子、叙事策略——拟标题和推荐框架时
直接复用）；**供给缺口**（现有文章普遍没做好的地方：深度不够 / 案例过时 / 人群错位，有则标注）。

**切入价值按需求窗口评**：**窗口内**（密度在最近 1–3 天快速形成、话题仍在上升）→ 跟进同角度是合理策略，
用拆解出的逻辑 + 自己的案例和表达跟进，正常评分；**窗口过后**（密度高且已持续多日）→
要求差异化角度（对立观点 / 更深一层 / 换目标人群），给不出差异化的照抄式选题 **切入价值封顶 4 分**；
**逻辑迁移**（把高频内容的形式逻辑搬到自己垂类的另一个话题上）→ 不受同题密度约束，按新话题正常评分。

**红线**：模拟的是逻辑和结构，不是搬运内容——标题公式可以复用，正文必须是自己的素材和表达。

## 选题卡格式

**类型标签**只有三个：`🔥 热点型` / `🌲 常青型` / `📚 系列型`（高频需求选题标 `🔥` 并注明「高频需求」）。

```markdown
### 选题 N：[选题名称]  [类型标签]
> 一句话说明切入角度与目标读者痛点
**切入角度**：为什么这个角度值得写。竞品怎么写的，你的差异化在哪。
**标题候选**：1.【干货型】… 2.【悬念型】… 3.【数字型】… 4.【反问型】…
**大纲预览**（预计 XXXX 字）：开头(300字)→[小标题一](800字)→[小标题二](800字)→[小标题三](600字)→结尾(300字)，各标段落主旨
**工作量**：⭐⭐⭐（预计 X 小时） ｜ **需要额外素材**：是/否（如需要，说明）
**摘要候选**（80–128 字，进 `article.yaml` 的 `digest`）：1. …（XX字）  2. …（XX字）

- 对应标题（20–28 字）："{公众号标题}" ｜ 热度：X/10 | 相关度：X/10 | 切入价值：X/10
- 点击率潜力：{高/中/低} — {原因，如「标题含数字 + 反直觉」}
- SEO 友好度：{seo_score}/10 — {引用 `wxart seo` 的数据}
- 推荐框架：{痛点型/故事型/清单型/对比型/热点解读型/观点型/复盘型}
- 推荐理由：{为什么值得写} ｜ 历史标记：{近 7 天有相同关键词则标「⚠️ 近期已覆盖类似话题」}
```

四模式展示形式：**A** 先给「调研发现」（竞品角度 / 关键数据 / 读者痛点 / 差异化机会）再给 3–4 张不同角度的卡；
**B/C** 给 10 个评分排序选题，交互模式下展示前 3–5 张完整卡、其余列标题 + 总分；
**D** 先给系列总览（系列定位 / 目标读者 / 发布节奏 / 系列逻辑 + 篇次表格）再给每篇卡。
各模式搜索词模板：A 用竞品 → 数据 → 读者视角三轮，B 用热点 → 趋势两轮，C 用 `article_category` /
`topic_direction` 代方向，D 用知识体系 → 竞品系列 → 读者需求分层三轮。每模式搜索调用控制在 4–6 次，
`web_search` 之后只 `web_fetch` 最有价值的 2–3 篇。
**用户选定后**输出精简交接卡（标题 / 摘要 / 切入角度 / 大纲 / 预计字数），再落盘。

## 两种运行模式

- **默认自动**：直接选总分最高的选题，写进 `state.yaml`，继续下一步写作，不暂停。
- **交互模式**（用户说「交互模式」或「每步确认」）：展示后**停下来等用户操作**，提示：
  「输入编号（如 1）→ 选定该选题 ｜『调整 + 意见』→ 按意见修改后重新展示 ｜『重新选』→ 换一批选题 ｜
  『组合 1+3』→ 融合多个选题 ｜ 系列模式：『先写第 N 篇』→ 按该篇进入写稿」。
  **禁止**不等用户选就继续；**禁止**假设用户会选某一个。

## 标题

**加载优先级**：用户当次指定（「用反问型」）→ 本篇 `article.yaml` 的 `title_style` →
`config.yaml` 的 `custom_title_style` > `default_title_style` → `{home}/presets/title-styles/` →
下面内置的 5 种。`title_style` 等预设字段在 config 里**须为 YAML 列表**；含多个候选时按本篇选题择一，
**写回本篇 `article.yaml` 同键为单元素列表** `[名]` 再往下走。**禁止盲选第一个**；
判断不了就把候选和说明摆给用户选。

| 风格 | 特点 | 适用 | 示例 |
|---|---|---|---|
| 悬念型 | 制造信息差或认知冲突 | 经验分享、反常识 | 我在 XX 行业干了 5 年，才发现这个真相 |
| 干货型 | 直接给结论、承诺价值 | 教程、方法论、工具推荐 | XX 入门指南：从零开始的 3 个关键步骤 |
| 数字型 | 用数字增强可信度和具体感 | 清单、技巧汇总、数据型 | 5 个让你少走弯路的 XX 技巧 |
| 反问型 | 用问句引发思考、制造共鸣 | 痛点型、观点型 | 为什么你的 XX 总是做不好？ |
| 故事型 | 场景感或故事开头，拉近距离 | 个人经历、案例分析 | 我花了 3 年试错，总结出这套 XX 方法论 |

每个选题给 **3–5 个混合风格**的候选，再收敛为一个主标题 + 两个角度不同但同样准确的备选。

**标题策略**：长度按 `title_max_length`，未配置时按 **25 字**收敛（候选可先在 20–28 字里构思）；
优先让手机信息流里一眼看清**对象、问题、收益**；数字、反直觉、痛点写法**只有正文确实支持时才用**，
不得虚构比例、时长或结果；主标题忠实对应核心判断，不为打开率承诺正文没写的东西；
写具体年份时用当年，别照抄模板里的年份。

**禁用套路**（以 `forbidden_title_phrases` 为准，常见项）：浅谈、万字长文、建议收藏、震惊、
不转不是中国人；UC 震惊体；过度夸张的承诺（「看完改变一生」「99% 的人不知道」）；学术体（论、之我见）。

## 摘要

- 长度 80–128 字（微信单图文 `digest` 上限 128 字）。配置里的 `summary_length` 更短时以配置为准。
- 写 1–2 个候选，落盘时取一个进 `article.yaml` 的 `digest`。
- **必须能独立成立**：说明核心判断或读者收益，不重复标题，不制造正文没有回答的悬念。
- **不得与正文首个 `>` 导语逐字相同**。摘要在后台列表与分享卡片上出现一次，导语在正文开头再出现一次——
  两处逐字重复，读者等于同一段话读两遍。两条的读者处境不同：摘要负责说清「为什么值得点」，
  导语负责交代「这篇讲什么、按什么顺序讲」。
- 关键词在标题、摘要或正文自然出现即可，不设出现次数和密度。

| 按场景 | 实战 / 应用 | 场景 A → 场景 B → 场景 C |

| 按问题 | 痛点 / FAQ | 问题 1 → 问题 2 → 问题 3 |

`plan.md` 写：系列总线、系列定位、目标读者、发布节奏、每篇的选题与顺序、彼此的依赖关系。
用户说「先写第 N 篇」时，**只为那一篇**建当轮任务目录，不要一次性把十篇目录全建出来——没写的目录只会变成噪音。

## 落盘

```bash
wxart run update --patch '{"topic":{"title":"…","keywords":["…","…"],"source":"热点抓取","framework_hint":"观点"}}'
wxart run step topic completed
```

`topic.source` 取值：`用户指定` / `热点抓取` / `高频需求` / `常青`；`topic.framework_hint` 取 7 框架之一
（见 [03-write.md](03-write.md) 的框架速查）。用户只要选题列表（不写正文）时，展示完 10 个选题即可；
用户选定后仍要落盘 `topic`，并提示「可以直接说『就写这个』进入写作」。

## 分支

| 情况 | 处理 |
|---|---|
| 用户已给选题（模式 A） | 落盘 `topic`，跳过 10 题生成，只出 3–4 个切入角度 |
| 热点命令整体失败 | `web_search "今日热点 {垂类}"` 替代，不阻断 |
| `search-articles` 失败或为空 | 跳过第 2 步，份额还给热点，选题构成退回默认 |
| `seo` 失败 | 自判关键词价值，标注「SEO 数据不可用」 |
| `history.yaml` 不存在 | 跳过去重与效果分析 |
| `stats` 不足 5 篇 | 只做去重，不做效果闭环 |

| 命中 `blacklist` | 该选题判 0 并淘汰，不进列表 |
| `style.yaml` 不存在 | 用当轮回答临时代替 `topics`，提示补全配置 |
