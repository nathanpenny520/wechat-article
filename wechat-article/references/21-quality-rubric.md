# 内容质量判据

判断一篇稿子**能不能交付**的标准。机械分数只提示语言风险，不参与放行判断。

## 1. 目的与边界

| 项 | 说明 |
|---|---|
| 用途 | 判断成稿在事实、判断和读者收益上是否可直接使用 |
| 不做 | 不判断文字「像不像人」 |
| 机械分数 | 只提示套话、碎句、节奏过齐等语言风险；**不参与放行判断**，不替代编辑判断 |
| 放行依据 | 五项编辑判断 + 阻断项 + `publishable` |

## 2. 五项编辑判断（各 1–5 分）

| 维度 | 字段名 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| 准确 | `accuracy` | 核心事实有直接来源；事实、推断、意见分得开；结论没有超出证据边界 | 事实基本正确，个别来源缺失或结论稍微越界 | 核心事实无来源或来源不支持，事实与推断混写 |
| 观点 | `viewpoint` | 核心判断明确，说清新增价值、适用范围和最强反方 | 有判断但边界模糊，或部分内容在重复常识 | 只有态度和常识堆叠，看不出核心判断 |
| 有用 | `usefulness` | 真正回答读者问题，给出可执行行动、决策条件或可迁移的理解框架 | 给了方向，但缺条件、步骤或完成信号 | 泛泛而谈，读者读完不知道做什么 |
| 合声 | `voice` | 符合账号语气且不被人格模板绑架；个人经历只来自本次用户材料；没有挪用范文 | 语气基本一致，个别段落像模板 | 语气与账号不符，或把他人材料写成作者经历 |
| 好读 | `readability` | 开头迅速进入问题；各节各有任务；论证连贯；标题准确；语言直接无重复 | 结构清楚但有个别冗段或重复 | 开头铺垫长，结构乱，表达重复 |

**交付门槛**：

```
平均分 ≥ 4      单项 ≥ 3      无阻断问题
```

## 3. 四类阻断项

任一项出现即不可交付。

| 编号 | 阻断项 | 判据 |
|---|---|---|
| B1 | 编造作者亲历身份 | 作者亲历、朋友、采访、对话、场景或身份是补造的 |
| B2 | 核心事实无来源或来源不支持 | 具体事实查不到来源，或来源不支持正文的说法 |
| B3 | 论点与证据脱节 | 核心论点与证据脱节，或把推断写成确定事实 |
| B4 | 没有明确交付 | 没有给目标读者明确的结论、行动或判断方法 |

## 4. 三类编辑决定

| 决定 | 语义 | 硬规则 |
|---|---|---|
| `pass` | 无阻断项，五项达到交付门槛 | 才能写 `article.md` |
| `revise` | 问题能在现有材料内修正 | **必须实际改稿并重新检查，不能只列建议** |
| `needs_input` | 材料不足 | **仅限**用户明确要求写其个人故事、关键材料缺失、且无法安全换框架；其他情况自动缩小主张或换框架 |

**最多两轮。** 第二轮仍未达标时不得假装通过：删除不可靠内容、缩小承诺，交付能被证据支持的版本。

## 5. `review-report.json` 字段

| 字段 | 值 / 来源 |
|---|---|
| `version` | 固定 `1` |
| `decision` | `pass` / `revise` / `needs_input` |
| `pass_number` | 只能是 `1` 或 `2` |
| `publishable` | 见下方计算式 |
| `dimensions` | 五项分数，各自必须是 1–5 的数值 |
| `dimension_average` | 五项平均，四舍五入两位 |
| `blockers` | 阻断项列表（对象数组） |
| `major_issues` | 主要问题列表，最多 5 个，按影响排序 |
| `notes` | 自由文本，默认空串 |
| `draft_chars` | 初稿字符数 |
| `final_chars` | 成稿字符数 |
| `edit_ratio` | 见下方定义 |
| `structure_changed` | 见下方定义 |

```
publishable = decision == "pass"
              and not blockers
              and min(dimensions) >= 3
              and average >= 4

edit_ratio       = 1 - SequenceMatcher(None, draft, final).ratio()   # 四舍五入 4 位
structure_changed = 提取两边 ^## 开头的标题列表，两列表不相等则为 True
```

`draft` 与 `final` 都必须非空，否则直接报错。

### 用法

```bash
wxart content-eval --draft D --final F --assessment A [--output review-report.json] [--json]
```

`--assessment` 是编辑判断 YAML/JSON，字段：`decision`、`pass_number`、`dimensions`（五项）、
`blockers`、`major_issues`、`notes`。

## 6. `brief.yaml` 与 `claims.yaml`

### `brief.yaml` 全字段

```yaml
version: 1
audience:
  who: "具体读者"
  context: "读者在什么情境下阅读"
  question: "读者真正要解决的问题"
goal:
  takeaway: "读完能复述的一个结论"
  action: "读完可以采取的行动；纯观点文可写判断方法"
thesis:
  statement: "全文核心判断"
  novelty: "相较常见说法新增了什么"
  boundary: "结论在什么条件下成立"
  counterpoint: "最强反方或替代解释"
personal_materials:
  available: false
  items: []                 # 只记录用户在本次任务明确提供的经历、观察或原话
framework: "观点"
sections:
  - purpose: "本节推进什么"
    claim_ids: [C1]
constraints:
  desired_length: "1200-2500 字"
  must_include: []
  must_avoid: []
```

硬规则：

- `constraints.desired_length` 默认 **1200–2500 字**。
- `thesis.novelty` **不得是唱反调**。找不到可靠新角度时，缩小问题、补适用条件或换更好用的判断框架。
- `goal.action` 必须与题目相称，不为凑「干货」制造步骤。
- 写稿前 `brief.yaml` 与 `claims.yaml` **先落盘**，不许先写正文再补任务书。

### `claims.yaml` 全字段与四类型语义

```yaml
version: 1
claims:
  - id: C1
    text: "正文准备表达的主张"
    type: fact              # fact / inference / opinion / user_experience
    source_ids: []          # 对应 sources.yaml 的 id；意见可为空
    status: supported       # supported / bounded / unsupported
    boundary: "适用范围或不确定性"
```

| 类型 | 语义 |
|---|---|
| `fact` | **必须有能直接支持它的来源**；否则删除或标 `unsupported`，不得进入正文 |
| `inference` | 要列出依据，并明确写明这是推断；边界写进 `boundary` |
| `opinion` | 是作者判断，不伪装成共识 |
| `user_experience` | **只能来自本次任务用户明确提供的材料**，并在来源账本标 `user_provided`；范文、模型记忆、人格示例都不是用户经历 |

**每一节至少服务一个主张；无法对应主张的段落默认删除。**

## 7. 个人材料边界

`personal_materials.available=false` 时的**禁止清单**：

- 作者经历过的事件
- 朋友 / 同事
- 现场对话
- 动作
- 时间地点
- 感官细节

**可写的替代**：我认为 / 我的判断 / 观察 / 问题 / 核心判断。

**人格要求私人开场或故事开场时自动改写**为观察、问题或核心判断开场，不得补造材料。

## 8. 四种安全内容增强策略

先完成 `brief.yaml` 与 `claims.yaml`，再按框架选**一项主策略**；材料不够时缩小主张或换框架。

| 策略 | 做法 | 输出到 |
|---|---|---|
| 观点 / 热点解读：**可支持的新角度** | 先浏览代表性已有解释，列出共识、分歧与被忽略的条件，选一个**有证据**的新贡献（更准确的因果解释 / 更清楚的适用边界 / 对具体读者的影响 / 更好用的判断框架）。不能为「尖锐」反对主流，不能把推测写成内幕 | `thesis.novelty` 与对应主张 |
| 痛点 / 清单：**行动可用性** | 逐节检查读者能否开始行动，补齐步骤、条件、成本、风险与失败信号。工具、参数、价格、版本都是事实，必须核实并注明时效。不是每节都要数字，不能把泛泛建议包装成确定答案 | `goal.action`、章节目的、主张边界 |
| 故事 / 复盘：**有来源的真实细节** | 只用用户明确提供或可靠来源明确记载的时间、地点、对话和细节。直接引语必须能逐字核对，转述要标明来源。材料不足时改用事实叙述或换框架，**禁止「合理重建」**、拼接人物、添加感官细节或替用户补经历 | `personal_materials`、来源账本、主张清单 |
| 对比：**决策条件** | 先定义共同标准，再比较证据、限制、总成本和适用人群。官方信息用于功能和价格；用户评价只代表被引用者的体验，不能外推。无法验证的「隐藏坑」不写。输出「什么情况下选什么」，不是整齐但无结论的优缺点表 | 主张边界与结论 |

**四条通过检查**：

1. 新角度能由已有证据和逻辑支持，不是为不同而不同。
2. 具体信息都有来源或明确边界。
3. 没有把第三方故事、范文片段或模型记忆改写成作者亲历。
4. 每个增强点都服务读者问题和核心主张；删掉后毫无影响的内容不加入。

## 9. 七个写作框架

| 框架 | 适用 | 推进骨架 |
|---|---|---|
| 痛点 | 读者有明确困难 | 场景 → 根因 → 解法 → 边界 |
| 故事 | 人物与变化是核心 | 冲突 → 选择 → 结果 → 含义 |
| 清单 | 读者要快速行动 | 目标 → 条目 → 用法 → 避坑 |
| 对比 | 需要做选择 | 标准 → A/B 证据 → 适用人群 → 建议 |
| 热点解读 | 事件正在变化 | 发生了什么 → 为什么 → 影响 → 观察点 |
| 观点 | 核心价值是判断 | 主张 → 证据 → 反方 → 边界 |
| 复盘 | 过程经验可迁移 | 目标 → 做法 → 偏差 → 学到什么 |

框架是组织工具，不是必须填满的模板；材料不足时缩小主张，不用空话补齐结构。

## 10. 语言风险 11 项检测（`wxart score`）

### Tier 1 六项（节奏与可读性）

| 检测 | 判据与阈值 |
|---|---|
| `sentence_length_stddev` | 句长标准差，**目标 ≥15**；得分 = min(1, stddev/25)。句子数 <5 时返回 0.5 |
| `sentence_length_range` | 句长极差 **目标 ≥30**，得分 = min(1, range/40) 占 0.6；**短段落占比**（1–5 字的非标题行）得分 = min(1, 短段数 / max(1, 字数/500)) 占 0.4 |
| `paragraph_length_variance` | **相邻段长差 ≤20 视为雷同**；得分 = 1 − 雷同对数 / 总相邻对数。段数 <3 返回 0.5 |
| `vocabulary_richness` | CJK **bigram TTR**，得分 = min(1, ttr/**0.7**)。CJK 字数 <20 返回 0.5 |
| `emotional_balance` | 负面标记句占比 **≤35% 满分**；超出后得分 = max(0, 1 − (ratio−0.35)×2) |
| `adverb_density` | 副词密度 **>3/100 字开始扣分**，扣 min(0.5, (density−3)×0.1)；**连续两句以副词开头每处 −0.3** |

### Tier 2 五项（语言风险）

| 检测 | 判据与阈值 |
|---|---|
| `banned_words` | **39 词套话表**，每个命中 **−0.2** |
| `sentence_integrity` | 碎句惩罚。允许量 = max(1, 字数/1000)；超出后得分 = max(0, 1 − 超出量 / max(3, 允许量×3)) |
| `real_sources` | **仅归因信号**，得分 = min(1, 命中数/5)。**不核实事实真伪** |
| `register_consistency` | 四个词汇带（专业冷词 / 口语暖词 / 网络热词 / 野生词），**用到 ≥3 个算「重度混用」**；≤2 个满分，超出后 max(0.4, 1 − (active−2)×0.3) |
| `insertion_control` | 自我更正/插入语 **≤3 满分**；超出后 max(0, 1 − (count−3)/8) |

39 词套话表（命中即 −0.2）：首先 / 其次 / 再者 / 最后 / 总之 / 综上所述 / 总而言之 / 此外 /
另外 / 与此同时 / 不仅如此 / 更重要的是 / 在此基础上 / 作为一个 / 让我们 / 值得注意的是 /
需要指出的是 / 不可否认 / 毋庸置疑 / 众所周知 / 事实上 / 显而易见 / 可以说 / 从某种意义上说 /
非常重要 / 至关重要 / 不言而喻 / 具有重要意义 / 发挥着重要作用 / 意义深远 / 影响深远 /
引发了广泛关注 / 引起了热烈讨论 / 总的来说 / 综合来看 / 由此可见 / 不难发现 / 通过以上分析 /
正如我们所看到的。

### Tier 3 可选 LLM 分

`--tier3 <0-1>`。不传则 Tier 3 记为不可用。

### 权重与总分

```
有 tier3  quality = t1×0.50 + t2×0.30 + t3×0.20     # 权重 50% / 30% / 20%
无 tier3  quality = t1×0.625 + t2×0.375            # 权重 62.5% / 37.5%

composite     = (1 - quality) × 100      # 越低风险越小
quality_score = 100 - composite          # 越高越好
```

### 命令与校准

| 参数 | 行为 |
|---|---|
| 默认 | 只打印 `quality_score`（一位小数） |
| `--verbose` | 逐项进度条 + 明细 + 最低分参数前三 |
| `--json` | 完整结果（tier1 / tier2 / tier3 / weights / param_scores / char_count） |
| `--calibrate` | 打印风格风险区间对照 |

```
needs_edit      0–49    Needs editing
review          50–69   Review suggested
clear           70–100  Few mechanical risks        # quality_score ≥ 70
```

### 两条禁令

1. **分数不参与 `publishable` 判断。** 不设机械及格线。
2. **禁止为分数制造错句、情绪配额或随机离题。**

**碎句惩罚的方向性约束**：完整句必须比刻意碎句得分高。检测设计上「碎句多」扣分，
不做「要求碎句」的正向激励。

## 11. AI 味诊断

分工：**本文只放判据表**，流程与自检顺序在 `04-review.md`。

### 指纹库（15 条）

| # | 特征 | 典型样子 | 信号 |
|---|---|---|---|
| 1 | 工整三段式排比 | 每节都来一组对仗排比，整齐得像 PPT | 中 |
| 2 | 「不是 X 而是 Y」滥用 | 「这不是工具，而是伙伴。」 | 强 |
| 3 | 面面俱到、没有取舍 | 利弊、前提、例外、适用人群全讲一遍 | 强 |
| 4 | 反复让步、两头讨好 | 「当然，这并不是说……」「诚然，也有人认为……」 | 中 |
| 5 | 命名仪式感 | 「我把这套方法称为『黄金三角法则』。」 | 中 |
| 6 | 情绪曲线太平滑 | 从头到尾一个温度，均匀的「温暖」「治愈」「赋能」 | 中 |
| 7 | 「你值得 / 愿你」式祝福收尾 | 「愿你在喧嚣中找到自己的节奏。」 | 强 |
| 8 | 翻译腔 | 「值得注意的是」「在某种程度上」「让我们来看看」 | 中 |
| 9 | 万能套话开头 | 「随着 AI 技术的发展」「在当今这个时代」 | 强 |
| 10 | 强行拔高升华 | 讲快捷键最后升华成「这是一种生活态度」 | 中 |
| 11 | 模板化假故事 | 「我有个朋友……」但细节全空 | 中 |
| 12 | 总分总八股 | 开头预告「本文将从三个方面」，结尾「总而言之」 | 中 |
| 13 | 过度规整的标点与节奏 | 句子长度高度均匀，几乎没有口语断句 | 弱 |
| 14 | 形容词 / 副词通货膨胀 | 「极其重要」「真正意义上的」 | 弱 |
| 15 | 概念名词扎堆、缺具体 | 满屏「赋能、闭环、抓手、底层逻辑」 | 中 |

**强 / 中 / 弱只表示「像不像 AI」，是诊断级**，与行动级（必须 / 建议 / 通过）是两套体系。
**AI 味默认 🟡，不阻断定稿。**

### 防误判阈值

| 情况 | 阈值 |
|---|---|
| 「不是 X 是 Y」 | **800 字内出现 ≥3 次**才算命中；单次、两次放过 |
| 排比 / 对仗 | 单处是好文笔；**几乎每节都在排比**才算 |
| 让步句 | 观点确有争议、需要交代边界时不算；**每个论点前都垫**才算 |
| 故事 | 有具体细节（时间、地点、对话、尴尬、数字）的不算假故事 |
| 升华 | 主题本就关于价值观 / 人生时，结尾谈意义不算拔高 |
| 拿不准 | **宁可不报**。文章干净就直接说干净 |

### 与写作规范的关系

- 规范已明令禁止的套话，由规范维度负责；本维度可指出，但**不要在两个维度各扣一次**。
- **规范鼓励的写法一律不算 AI 味**：用「你 / 大家」直接对话、生活化类比、短句短段、口语化、
  固定互动收尾（「点赞、在看、加星标……下期见」）。
- 一句话原则：规范管「该不该这么写」，本维度管「读起来像不像 AI」。

### 体裁宽严

| 体裁 | 宽严 |
|---|---|
| 公众号长文 / 干货 | 最严；八股结构、面面俱到、强行升华更刺眼 |
| 短文案 / 朋友圈 / 推送语 | 放宽；重点看套话开头与空洞祝福 |
| 标题 | **不按正文标准扣**；只在确实千篇一律时提示 |

**AI 味默认 🟡（诊断级），不阻断定稿。**

## 12. 人工修改率

- `edit_ratio` 用于**观察初稿稳定性**，**不设单篇硬门槛**。
- 人工后续修改率目标 **≤15%**。
- **无样本时不得宣称达标。**

## 13. 五个评测用例

| # | 用例 | 检验什么 | 合格表现 |
|---|---|---|---|
| 0 | `analysis-with-sources` | 有来源的分析文：任务书、主张、初稿、成稿是否齐备，事实 / 推断 / 意见是否分开 | 目录内有 `brief.yaml`（含 audience / goal / thesis / personal_materials）、`claims.yaml`（事实主张关联 `sources.yaml` 来源编号）、`draft.md`（不被当成最终成稿）、编辑通过后的 `article.md`；`review-report.json` 中 `decision=pass` 且 `publishable=true`；核心结论没超出来源支持范围 |
| 1 | `practical-guide-actionability` | 读者能不能按文章开始行动 | `brief.yaml` 明确读者行动，正文实际交付对应步骤或判断方法；建议含必要条件、边界或失败信号，不堆泛泛建议；工具、版本、价格、数字等具体信息无来源时不写成事实 |
| 2 | `no-personal-material-no-fabrication` | 没有个人材料时不得编造亲历 | `brief.yaml` 中 `personal_materials.available=false`；正文没有用户未提供的个人事件、人物、对话、时间地点或感官细节；人格退回观察、问题或核心判断开场，而非私人场景 |
| 3 | `user-provided-story` | 只用用户给出的经历，不做扩写 | `brief.yaml` 逐项记录用户提供的事实；`sources.yaml` 中对应材料状态为 `user_provided`；没有为增强画面感补造人物身份、现场对话和感官细节 |
| 4 | `weak-draft-must-revise` | 问题稿必须真改而不是只给建议 | 第一次编辑决定为 `revise`，实际删除或补证、重写核心判断与读者交付；`review-report.json` 的 `pass_number=2` 且 `edit_ratio > 0`；最终 `blockers` 为空、`unsupported` 主张不在成稿中；最终 `decision=pass` 且 `publishable=true` |
