# 配图：方法与工具

配图分两层，**先方法后工具**，顺序不能颠倒：

| 层 | 回答什么 | 谁做 | 产物 |
|---|---|---|---|
| **方法（判断）** | 这里要不要图？要图还是组件？用哪个形态？用哪个媒介？写什么画面？ | 你 | `imgs/prompts/*.md`、`imgs/outline.md`、`article.yaml` 的 `image_medium` |
| **工具（生成）** | 把 prompt 变成图片文件 | `wxart image …` | `cover.png`、`imgs/*.png`、日志 |

**默认工具是 aws 引擎**：比例结构化、出图后确定性检查、`check` 可复查。备选 wx 引擎（`wxart image --engine wx …`）当 aws 端点不可用或需要多 provider fallback 与费用硬上限时用。

## 读什么 / 产物

读 `article.md`（或 `article-illustrated.md`）、`article.yaml`（本篇预设）、`config.yaml`（`cover_aspect`、`image_density`、`caption_style`、`tone`）、`article.html`。
产物：`cover.png`（文章目录**根**）、`imgs/**`、`article-illustrated.md`（**原始 `article.md` 永不被覆盖**）、`img_analysis.md`（用户供图时）。

## 1. 图位判据：这张图要不要

> **删掉这张图，读者是「看不懂」还是「读不下去」？**

| 答案 | 结论 |
|---|---|
| 看不懂 | **信息位**，必须留，且必须带文章真实内容 |
| 读不下去 | **节奏位**，可留可换，纯粹给眼睛休息 |
| 都不影响 | **候选删除** |

无信息量的氛围图会稀释信息密度，让读者划得更快、退出更早——排版的目的是降低阅读成本，不是填满页面。

**删除上限（硬）**：**每篇最多删 1 个图位，并在结果里写明删了哪个、为什么。** 判定要删 2 个以上时**不要自行删**——那说明 `image_density` 和这篇内容对不上，把这个判断告诉用户，由他决定改配置还是照配。**把本篇 `image_density` 改小是同一件事**（效果等于一次删掉若干图位，删除上限管不到它），同样必须先告知用户。

密度口径与写作侧同一套定义：`每节一图`＝每个 `##` 各一张不多不少；`按需配图`＝只在文字讲不清的地方配；`少图`＝全篇只配 1–2 张最关键的；`多图`＝每 2–3 个自然段一张。

## 2. 图还是组件

排版侧的版式组件和信息位配图干同一件事，**必须先分工**，否则同一份内容会既做成卡片又画成图。哪些组件真的够得到、它们的 `:::` 语法与硬约束，见 [05-format.md](05-format.md)。

> **内容里有没有空间关系？** 有大小、流向、嵌套、位置 → **用图**；只是文字并列、对照、枚举 → **用组件**。

但判据下面还有一层现实约束：写作侧只产出标准 markdown，`:::` 私有块语法是明令禁止的，所以**只有能被标准 markdown 触发的组件才存在**。判给一个够不到的组件，等于图也删了、组件也没有。

| 形态 | 归谁 | 为什么 |
|---|---|---|
| 数据图表 | **图** | 柱子高低直接表达大小关系；卡片只能把数字列出来让读者自己比 |
| 流程步骤 | **图** | 箭头表达「流向」；组件的竖线只表达「这几条是一组」 |
| 结构分层 | **图** | 大括号和嵌套是空间关系，组件只能平铺成几行 |
| 对比两栏 | **图** | `compare` 只有 `:::` 一条路，写作侧够不到 |
| 清单要点 | **图** | 同上：`checklist` 块够不到；`- [ ]` 是低频写法，不能指望它出现 |
| 金句卡片 | **组件** | `> 金句。 —— 出处` 是标准 markdown，写作侧有硬配额保证每篇出现一次 |

**「数字 → 组件」是错的**：数据图表恰恰全是数字，却是图赢得最彻底的一项——决定因素是有没有大小关系要看。

**金句卡片是唯一要防重复的一项**：排版已会把它排成金句卡，再为它画一张配图，同一句话会出现两次。

**判不准的时候优先图**——组件够不到就是彻底没有，而多一张图只是多花一点钱。

## 3. 封面：七步推导

封面**必须脚本生成**，产出为文章目录下的 `cover.png`（或 `.jpg`/`.jpeg`/`.webp`）。**禁止**把素材库文件直接复制成 `cover.*`；例外是用户明确上传并声明「只用这一张」，此时结果里要注明「用户指定封面」。

1. **找核心张力**。读标题、摘要、开头三段，问「这篇文章里，什么变成了什么？」，用一句含动词或对比的话写下来（如「手工排版三小时 → 一条命令」）。写不出变化就写它讲的那个概念（「上下文窗口」「技术债」）。两者都写不出 → 只能走氛围，直接跳第四步。
2. **定关系类型**。

| 句子长什么样 | 类型 | 封面怎么做 | 适合 |
|---|---|---|---|
| A 和 B 并列对比 | **并置** | 两个东西并排放，让读者自己比 | 评测、前后对比、两种做法 |
| A 变成了 B / A 和 B 是一回事 | **融合** | 把两个东西合成一个物体，看得出是哪两个 | 转化、结合、同构 |
| 一个抽象概念 | **替代** | 用一个具体的物代替它 | 原理、方法论、观点 |
| 没有张力，只有情绪 | **氛围** | 不做隐喻，只做光和空间 | 随笔、故事、感悟 |

融合最出彩但最难，替代最稳。**拿不准就替代。**

3. **找视觉隐喻**。要一个具体的、单一的、能画出来的东西承载第一步那句话。列三个候选，按三条筛：一眼能读懂、有一点意外、和这个号的调性搭。
   **禁止的陈词滥调**（AI/科技类尤其要躲）：机器人、发光的大脑、电路板做的大脑、伸出的机械手、握手、灯泡、齿轮堆、二进制雨、蓝色光环、抽象的「AI 赋能」光线——这些是模型的默认值，等于没给 brief。
   范例（范例不是模板，同一篇换个隐喻完全可以）：

| 文章讲的 | 隐喻 | 类型 | 成立的理由 |
|---|---|---|---|
| 散落的规矩被收进配置 | 无数光点从四周汇聚成一个发光核心 | 替代 | 「汇聚」是动作本身，不解释也能懂 |
| 刚跑通的新流程 | 一株嫩芽顶开土壤，土屑还悬在半空 | 替代 | 「刚刚」被定格在那一瞬 |
| 拆解一套体系 | 一整张纸折出的微缩景观，折痕清晰可见 | 替代 | 折痕就是结构 |
| 只有一个出口 | 混凝土长廊尽头唯一的一道光 | 替代 | 纵深让「唯一」有分量 |
| 自然生长与工程设计同构 | 树根向下渐变成电路走线，无缝过渡 | 融合 | 两者共用同一条线，分不出边界 |
| 红利期终将过去 | 沙漏上半是运转的城市，下半是坍成沙的废墟 | 融合 × 对立 | 上下是同一件事的两端 |
| 一次优化前后 | 同一个几何体，左边粗糙原石，右边通透水晶 | 并置 × 对立 | 形状相同才让人比材质 |
| 那个没人提的问题 | 满座的会议桌，只有一把椅子被推开背对着 | 替代 × 对立 | 用缺席表达在场 |

4. **选形态**。判据只有一条：**这篇文章的主体，在 345px 宽的缩略图里能不能被一眼认出？**

| 自明（能认出） | 抽象（认不出） |
|---|---|
| 一道菜、一个人、一处空间、一个情绪场景 | 一个方法、一个观点、一次对比、一套流程 |
| → 菜品特写 / 人物出镜 / 场景实拍 / 剧照氛围；**默认不加字**，主体自己会说话 | → 纯色大字 / 图上压字 / 信息表 / 数字冲击 / 对比式 / 截图标注；**字就是全部**，画面只是背景 |

介于两者之间的教程、产品评测 → 扁平插画 / 产品实拍（插画或产品打底 ＋ 一句短钩子）。
抽象类里有三个**专用形态，命中就优先用**：标题带数字 → **数字冲击**（100 个大号分析里排第一）；讲前后/方案对比 → **对比式**（排第二）；讲怎么操作 → **截图标注**（工具号标配）。

**12 个封面形态与文案规格**（文案规格按信息流尺寸标定过，**一字不改**）：

| 形态 | 自明度 | 文案规格 |
|---|---|---|
| `纯色大字` | 不自明 | **画面的全部**：4–7 字钩子，极粗无衬线黑体，字高 **35–40%**、横向占 **45% 以上**，居中；可在下方加一行字高为主标题 1/4 的副标题 |
| `图上压字` | 不自明 | 必须有：4–7 字钩子，纯白粗黑体，字高 **16%**，左对齐排在遮罩上，从画面 **8% 排到 62%** |
| `信息表` | 不自明 | 必须有标题：粗黑体居中在结构上方，字高 **14%**；格内文字小是允许的 |
| `数字冲击` | 不自明 | **数字就是主体**：数字占高 **70%**；单位字为数字的 **1/5**；说明短语 4–6 字，字高 **18%**，垂直居中对齐数字 |
| `对比式` | 不自明 | 必须有，且**必须放在顶部的实心横幅上**：横幅高占画面 **24%**、横贯全宽；白字粗体，字高占横幅 **60%**。放两半交界处会被切顶（实测过） |
| `截图标注` | 不自明 | 必须有：箭头指向的右侧空白区写 3–5 字红色极粗中文，字高 **22%** |
| `扁平插画` | 中间 | **建议加字**：4–7 字钩子，粗圆体，字高 **20%**，排在右侧留白区 |
| `产品实拍` | 中间 | 必须有：4–7 字钩子，极粗黑体，**纯白色**（深底必须用纯白，浅灰在缩略图里会消失），字高 **26%**，撑满右侧留白区 |
| `菜品特写` | 自明 | **默认不加字。** 需要强调做法或结论时，才在顶部或底部压一条字高 **12%** 的粗字，白字配深色半透明底 |
| `人物出镜` | 自明 | **默认不加字**（人物状态已经说明一切）。要加则用 `图上压字` 的规格 |
| `场景实拍` | 自明 | **默认不加字。** 要加则用 `图上压字` 的规格 |
| `剧照氛围` | 自明 | **默认不加字**（情绪型封面加字会破坏留白） |

模板五字段（`用于`/`主体`/`影调`/`文案`/`版式`）**一个都不能缺**；**「文案」不可缺省**——缺了产出的是背景图不是封面。用户自定义放 `presets/cover-styles/<名>.md`，同名覆盖内置。

**避免撞形**：形态只有 12 个，一个账号发几十篇必然重复。差异靠模板里的**可轮换维度**（视角、容器、台面、光这类），每次各选一个值。**记录本账号最近 3 篇用过的「形态 ＋ 维度组合」，新的一篇避开。**

5. **按信息流尺寸布局**。封面在信息流里只有 **345×147px**（iPhone 逻辑像素，头条），次条更小。所有布局决定都要在这个尺寸下成立，不是在 1408×599 的原图上。**标题是第一元素，画面是它的背景**，不是反过来。硬规矩：
   - 标题 **4–7 个字**，从文章标题里提炼最刺激的那个钩子；
   - **字高占画面高度 25–35%**，横向撑满它所在的那一半。**低于 20% 和微信自带的标题一样大，等于白写**；
   - 粗体，浅底深字或深底浅字，对比拉满（深底可加柔和辉光）；
   - 主体**占满画面高度的一半以上**，靠近标题；
   - 视觉元素**不超过 3 个**（标题算一个）；
   - 除标题外画面里没有别的文字；
   - 布局二选一：**主体在左四成、标题在右六成**（默认），或**标题居中、主体做底**。别发明第三种。
   1:1 分享卡片由 `pic_crop` 从中截取，是降级视图，**不为它牺牲主图**。
6. **写成散文**。150–300 字，顺序：**场景 → 主体细节 → 光 → 氛围 → 它像什么不像什么 → 标题**。三个技巧：**正面描述**（要「空旷的街道」不要「没有车的街道」——「不要 X」经常把 X 召唤出来）；**像什么、不像什么**（「像天文台的长曝光观测图，而不是一张科技海报」能纠正模型的默认审美）；**写细节不写形容词**（「土屑还悬在半空」比「充满生机」有用得多）。标题文案的确切文字、位置、字体感、颜色、大小都要写在里面。
7. **回看六条**：① 标题的字对不对、全不全（模型偶尔把「一」画成「5」）；② 主体是否在该在的位置、标题区有没有被侵占；③ 元素是否不超过 3 个；④ **缩到 345px 宽**还能不能一眼读出标题、认出主体；⑤ 和文章有没有关系；⑥ 形态选对没有（自明的主体被字挡住了？抽象的内容没有字？）。
   不过关就**回到出问题的那一步改**，不要不改 prompt 就盲目重跑。另外有一条**不必肉眼看**：日志里若出现「只剩 N%……腰斩」的 WARN，说明端点没按 `aspect` 出图、构图已被裁废，**直接重跑**。

## 4. 正文配图：六步

1. **先问要不要这张图**（见第 1 节）。
2. **选形态**。标记类型只定方向，**以内容为准**：

| 这段在讲 | 形态 | 位 |
|---|---|---|
| 操作顺序、方法步骤 | 流程步骤 | 信息位 |
| 系统构成、层级关系 | 结构分层 | 信息位 |
| 数字、趋势、指标 | 数据图表 | 信息位 |
| 前后差异、方案取舍 | 对比两栏 | 信息位 |
| 并列要点、检查项 | 清单要点 | 信息位 |
| 抽象概念、观点 | 概念隐喻 | 节奏位 |
| 使用场景、代入感 | 场景还原 | 节奏位 |
| 全文最值得单独记住的一句 | 金句卡片 | 节奏位 |

写作侧的标记类型只有四个，定的是**图位不是形态**：`封面`（走第 3 节）、`实证`（**真实素材，不生成**，来源说明写进 `imgs/sources/`）、`信息图`（信息位）、`氛围`（节奏位）。存量草稿里的 `流程图`/`对比` 按 `信息图` 处理。「手绘」不是形态，是**媒介**（第 5 节）——任何信息位形态都能用手绘画出来。

**8 个正文形态与文案规格**：

| 形态 | 位 | 文案规格 |
|---|---|---|
| `流程步骤` | 信息位 | **必须有，且必须是文章里的真实步骤名。** 每格粗体步骤名加一行小字说明。主体：3–5 个圆角矩形横向等距排列，箭头细线相连，当前重点那格加深描边 |
| `结构分层` | 信息位 | **必须有真实层名。** 每层粗体层名，层内小块各有短标签。主体：3–4 层横向长条自上而下堆叠，左侧可加竖向括号做整体标注 |
| `数据图表` | 信息位 | **必须有真实数字与标签。** 数值标在柱顶或点旁，横轴标签用中文。主体：柱状条或折线，末端关键点放大标注，纵轴不画刻度线、只留极淡水平网格 |
| `对比两栏` | 信息位 | **必须有真实对比项**，两栏行高严格对齐、方便横向比较。主体：一条细竖线把画面分成等宽两栏，每栏顶部一个色标签，下面 3–4 行带勾/叉的条目 |
| `清单要点` | 信息位 | **必须有真实要点，每行控制在 4–6 字。** 必须明确写「画面上除这几行中文外没有任何图形、符号或图标」。主体：3–5 个正圆形排成一列，圆内白色数字，右侧横排一行粗体中文短句 |
| `概念隐喻` | 节奏位 | **不加字**（隐喻自己会说话，加字反而解释过度）。主体：一个视觉隐喻，居中，背景空无一物 |
| `场景还原` | 节奏位 | **不加字。** 主体：文章里写到的那**一个具体时刻的局部特写**，不拍全景不拍脸 |
| `金句卡片` | 节奏位 | **这个形态的全部内容就是文案。** 正文金句 15–30 字，居中，占画面宽度 **70–80%**；横排按语义断行、不要断在词中间；右下角一行小字：作者名或公众号名，字号是正文的 **1/4**，低对比度 |

3. **取真实内容（信息位必做）**。信息位的每一个字都必须来自文章，不能让模型自由发挥。从图所在那一段及前后文里，抄出真实的步骤名、层级名、数值与单位、对比项、要点句，写进 prompt 时**逐字给出**。实测：让模型自己填清单内容，它会生成「保持高效工作状态」「享受生活每一刻」这类无关鸡汤，还自带 emoji。节奏位跳过这步。
4. **定媒介**（第 5 节，每篇一次）。
5. **套模板与维度**。照抄该形态模板的字段，文案规格（有无字、字号、位置）一字不改。从「可轮换维度」里各选一个值；**同一篇文章内的多张配图必须错开维度组合**——连着三张流程图都用同样的方向、格数、配色，读者会觉得在重复看同一张。
6. **写成 prompt**。`aspect: "16:9"`，正文宽 **1080px**。正文图的信息密度**可以比封面高**——允许文字与细节，目的是辅助理解，不是三秒抢眼球。**回看四条**：① 中文有没有错字、信息位内容是不是文章里的真实内容；② 有没有混进 emoji、英文标点、多余说明小字；③ 手机上占满屏宽时能不能读清；④ 和这一段文字是否真的相关。不过关回到出问题的那一步（内容错了回第三步，AI 味重回第四步换媒介，混进杂物回第六步换正面描述，形态不对回第二步）。

## 5. 媒介：一篇文章一次，按内容定

**这一步在生成任何图之前做，一篇文章只做一次，本篇所有信息位配图共用同一个媒介。** 节奏位（概念隐喻 / 场景还原 / 金句卡片）不受这条约束。

**为什么换媒介就没有 AI 味？** 不是「手绘自带不完美的痕迹」——把同样内容画成**终端窗口**（等宽字、纯色底、像素级整齐，一点不完美都没有）照样零 AI 味。真正的原因是：**白板、牛皮纸、黑板、终端、批注过的打印稿，都是读者在生活里真见过的载体**；而「扁平矢量信息图」不是任何人会遇到的实物，它只是一个模板。

| 媒介 | 长什么样（**整句抄进 prompt**） | 适合 |
|---|---|---|
| 马克笔白板 | 磁性白板、金属边框、手写行楷、红笔圈注、旧字迹残影 | 讲解、流程、对比。像刚开完会 |
| 方格笔记本 | 格子纸、钢笔手绘、墨迹洇开、涂改、红笔波浪线 | 结构、图表、需要对齐的内容 |
| 便签手写 | 彩色便签贴在木桌上、翘边投影、签字笔字迹 | 清单、要点、思路整理 |
| 黑板粉笔 | 深墨绿黑板、粉笔飞白、云雾状旧擦痕、槽里的粉笔头与板擦 | 教学、科普、课堂感 |
| 牛皮纸圆珠笔 | 牛皮纸折痕、蓝黑圆珠笔、划掉重写、咖啡渍 | 随笔、清单、个人向 |
| 终端等宽 | 深色终端窗、等宽字、青色正文 ＋ 橙色提示行、方块光标 | 开发者号、命令行/配置类内容 |
| 打印稿批注 | A4 印刷体 ＋ 红笔圈划、页边手写批注与箭头、卷边 | 拆解、评测、逐条挑毛病 |
| 扁平矢量 | 圆角矩形、箭头、低饱和色块 | **只用于 To B / 产品文档风的号。这是 AI 味的默认值，别的场合别选** |

**三顺位选择规则**：

1. **内容先定**（第一顺位，硬）。命令行/配置/报错/代码 → 终端等宽；逐条挑毛病/评测拆解/审稿 → 打印稿批注；流程/方法讲解/开会感 → 马克笔白板；清单/要点/思路整理 → 便签手写；结构/层级/需要对齐的图表 → 方格笔记本；教学/科普/入门 → 黑板粉笔；随笔/个人经历/心得 → 牛皮纸圆珠笔；To B 产品文档/企业向 → 扁平矢量。
2. **`tone` 否决**（第二顺位）。`tone` / `account_type` **只用来排除明显违和的**（严肃财经号不要黑板粉笔，个人随笔号不要扁平矢量）。它不圈定范围、不直接决定用哪个——`tone` 是账号级、永远不变的，让它决定媒介就等于每篇都一样。
3. **平手才避开上一篇**（第三顺位）。**只有当两个媒介同样合适时**才看上一篇用了什么，选另一个。**只避开上一篇，不是最近三篇**——按 `tone` 圈出来的集合只有三四个，排除 3 个之后恒定只剩 1 个候选，「挑与本篇内容最搭的那个」永远无事可做，媒介会退化成一个固定循环。**内容明确指向某个媒介时不要为了避重复而换**：一篇讲命令行的文章配白板，比连着两篇终端窗更糟。

**两条硬规则**：

- **prompt 里必须带上媒介的完整物理描述**，上面那张表「长什么样」一列**整句抄进去，放在 prompt 开头**。只写「米白方格笔记本媒介」这种六字名号是不够的：实测四篇里三篇的媒介被模型忽略，出来的是带淡淡格子背景的扁平矢量图。只有「终端等宽」落地了，因为它本来就是纯色平面、不靠质感。
- **本篇选定后必须立刻写进 `article.yaml` 的 `image_medium`**，配图收尾时核对这一行非空。它是下一篇「平手时避开上一篇」的唯一依据——实测 45 份 `article.yaml` 里 44 份是 `image_medium: ''`，等于第三顺位查到的永远是空，避重复根本没在跑。篇内必须统一（三张图分别是白板、便签、笔记本，读起来像三个人做的）；**篇间不强制换**，换不换由内容决定。

## 6. 比例与尺寸

| 项 | 值 |
|---|---|
| `cover_aspect` 默认 | **2.35:1** |
| 信息流实际显示尺寸 | **345×147px**（iPhone 逻辑像素，头条）；次条更小 |
| 封面尺寸参考 | 2.35:1 → 900×383；16:9 → 1080×608；1:1 → 1080×1080 |
| 封面文件 | JPG / PNG；单张建议 ≤ 2MB |
| 正文图 | **16:9，宽 1080px**，占满手机屏宽 |
| 单张大小上限 | **封面 10MB（压缩前）／正文图 1MB**——微信接口的硬限，发布脚本会自动压缩 |
| 正文列宽 | 微信正文有约 20px 固定边距，满宽 **≈335px**；块级元素和图片都被限制在这个列宽内，**无法贴到屏幕两边** |

比例的落地细节：`image_create.py` 先按 `aspect` 映射到 API 支持的最接近尺寸（2.35:1 → 1792x1024），装有 Pillow 时再居中裁切到目标比例（→ 1792x763）；未装保留原尺寸并给 `[WARN]`。

## 7. prompt 硬规则

- **`aspect` 值必须加引号**。未加引号的 `16:9` 会被 YAML 1.1 解析成整数（`16:9` 里的冒号让解析器当成时间/进制），脚本会尽量反推，但不保证所有写法。写 `aspect: "2.35:1"`。
- **`fit: preserve` 是默认，不裁。** 默认原样保存 API 返回的完整图，避免方图被裁成横图后标题或脚注消失。`aspect` 是**请求目标，不能证明返回图已经合格**——比例不符会告警（`[WARN] 返回图 WxH 与目标 A 不符；已保留完整原图，未裁切`），但不再自动裁掉文字。只有确认边缘可舍弃时才显式 `--fit crop`（或在 frontmatter 写 `fit: crop`）恢复居中裁切。**命令行覆盖 frontmatter。**
- **腰斩 WARN 与「连着两次就别再试」**：日志出现「只剩 N%……腰斩」说明端点没按比例出图、构图已被裁废，**直接重跑，不用打开图片确认**。**不要仅为了消除告警重复付费生成**；连续两次仍是同一 WARN 就说明该端点不遵守这个比例，改配置或换端点也不会一次就好——停下来说明情况。
- **负向指令压不住模型的默认形态。** 清单、卡片这类版式在训练分布里绑定了「卡片阴影 ＋ emoji ＋ 说明小字」，写「不要 emoji」「不要卡片」**无效**。必须正面描述一个不含这些元素的具体画面：「纯米白色背景，整幅画面没有任何纸张、卡片、阴影或边框，背景与画布融为一体。画面上除了这四个数字和四行中文，没有别的任何图形、符号、图标或文字。」
- **不要写「不要复杂纹理」。** 媒介的全部价值就在纹理（白板的旧字迹残影、方格纸的墨迹洇开、牛皮纸的折痕与咖啡渍），「不要复杂纹理」和它们出现在同一份 prompt 里时模型会选择前者——实测八张信息位配图六张退化成扁平矢量。通用构图要求只写：元素不堆砌、信息层次清楚；充足留白，主体元素呼吸感；主视觉居中或按内容需要布局；突出核心信息。
- **不要写「文字清楚准确」这类要求。** 手写字天然不如矢量字锐利，模型会为了满足「清楚」而放弃手写。要表达可读性就写「手写但笔画清楚、字号足够大」，把它限定在媒介之内。
- **图中文字必须是中文，且必须在 prompt 里直接写出要显示的那几个字**（如左侧「传统对话AI」、右侧「OpenClaw」、步骤「立项」「开发」「上线」）。**禁止**只写 `labels in Chinese` 或 `Chinese or English OK` 这类元描述——模型需要知道具体写哪几个字，不是知道用什么语言。prompt 本身可中英混排，「会出现在图上的字」必须用中文写出。
- **⛔ 不许用绘图库重画。** 不许因为「API 出来的字有裁切或多余文字」就改用 matplotlib / PIL / SVG 按同样文案重画。后果三条：媒介和形态整套方法论被绕开（绘图库只画得出扁平矢量，正是「AI 味的默认值」那一档）；**钱付了两遍**（先调 API、判定不合格、再重画，API 那次白花）；**全程无记录**，日志里看不出来，只有翻 PNG 元数据才发现（实测 22 张里 12 张的元数据写着 `Software: Matplotlib`）。当前模型的中文渲染已经没有问题——**出字问题先改 prompt 重试，不要换工具。**
- 通用规则补充：所有 prompt 都要有布局结构（构图、区域划分、视觉流向）、具体内容（文章中的实际数据/术语/关键词）、视觉关系（元素之间如何连接、对比、层次）、语义颜色（红＝警告、绿＝增长、蓝＝科技）、风格特征（线条处理、纹理、氛围）、比例。**抽象优于具象**：「AI 赋能」→ 光线连接感，不要画机器人。**一图一个焦点。**

## 8. 工具层

```bash
wxart image generate <prompt.md> -o cover.png [--size 1024x1024|16:9|2.35:1] \
       [--fit preserve|crop] [--quality standard|hd] [--retries N]
wxart image batch <prompts_dir> -o <imgs_dir> [--skip-existing]
wxart image check <image>
wxart image test          # 连通性自检，会真的生成一张图，按张计费
wxart image styles        # 列出真实存在的形态名，并校验 config 候选池
wxart image-prepare <article_dir> [--cover 02-x.png] [--overwrite]
```

**没有生图模型时的封面降级**：`wxart cover "6字钩子" "一行副标题" -o cover.png` 会用 Pillow 在本地合成一张「纯色大字」封面（2.35:1、长边 1408、字高 37%、横向 ≥45%，同时导出一张 345×147 缩略图供核对可读性）。它**只做封面**——正文配图仍然必须由生图模型产出，不许用绘图库重画。用这条路径时要在汇报里说明「封面为本地合成，非模型生成」。

**先跑 `styles`**：退出码 1 说明 `config.yaml` 的候选池里有不存在的形态名——**先改名再往下走**。实测网站导出的 config 写过「对比说明 / 板书白板 / 氛围烘托」，三个都没有对应模板（真名是 `对比两栏` / `概念隐喻` / `场景还原`，而「板书白板」是**媒介**不是形态）。挑中这种名字只能让模型自由发挥，整套形态方法论静默失效。

> `styles` 的列表里会多出 `README` 与预设包附带的 `简约.example`，所以它的行数比形态数多。**形态数以本文正文的 12 个封面 / 8 个正文为准**，不要按列表条数判断。

**prompt 文件的 frontmatter 字段**：`aspect`（如 `"2.35:1"`，**加引号**）、`size`（`1024x1024` 等像素串，或比例）、`fit`（`preserve` / `crop`）、`quality`（`standard` / `hd`）、`resolution`（Gemini 档位；**分辨率问题勿设 `4K`，实测会连比例一起失效**）、`role`（`cover` / `body`，也认 `封面` / `正文` / `article`）、`type: source`（取证说明，batch 会跳过）。`role` 不写时按文件名带 `cover` / `封面` 判断是不是封面。

**退出码语义**：

| 码 | 含义 | 处置 |
|---|---|---|
| **0** | 成功 | 继续 |
| **1** | 硬错误（API 失败、文件缺失、**跑错目录**等） | 按失败四分类处理，必须分类并摘要报错，不得只说「生图失败」 |
| **2** | 图片模型未配置（stderr 含 `[NO_MODEL]`） | Agent 支持生图且用户明确同意时，读 `imgs/prompts/*.md` 用自身多模态能力按**相同 prompt** 生图；否则明确告知不能完成生图，给二选一 |

**`check` 的阈值**（出图后的纯代码检查，不需要任何模型）：

- **长边 < 900px → FAIL**。900×383 是官方推荐的 2.35:1 封面尺寸。**这条线只卡封面**——正文插图只在 375pt 宽的正文里显示，达不达 900px 读者看不出来，按这条线重生成是为读者看不见的差别付费。
- **整图灰度标准差 < 8.0 → FAIL**（近单色，疑似生成失败／空白）。

**`_write_if_not_worse` 与 `_clear_stale_siblings`**：

- `_write_if_not_worse`：新图不合格、而磁盘上已有一张合格的同名图时，**保留旧图不覆盖**并打 WARN。端点的分辨率是随机的，重跑同一条 prompt 完全可能拿到更差的一张（实测补跑两张，其中一张把已合格的图覆盖成了 683px）。
- `_clear_stale_siblings`：写出新图后**删掉同名不同后缀的旧图**（同一 prompt 这次 PNG 下次 JPEG）。**这一步会让引用断掉且不报错**——`article.md` / `article.html` 里的 `imgs/xxx.png` 指向了不存在的文件。脚本会打 WARN 提示把 `imgs/旧名` 改成 `imgs/新名`。**重跑后必须按文件名主干重新匹配实际存在的文件，两个文件一起改。**
- **每次调用都会打印生图 API 调用次数**（`本次调用生图 API N 次（按张计费）`）；`--retries` 只处理现有质量检查失败，**不保证修复比例或错字**，默认 `0`（重试按张计费，被丢弃的候选图不落盘——目录里一张废图都看不到，钱却已经花了）。批量重跑加 `--skip-existing`，已生成合格的不会重复付费。

**wx 引擎备选（`--engine wx`）**：

```bash
wxart image --engine wx --prompt P --output O [--size cover|article|vertical|square|WxH] [--provider doubao]
wxart image --engine wx --manifest images.json [--max-images N] [--max-cost F]
```

- `--size` 预设 `cover` / `article` / `vertical` / `square`，或直接给 `WxH`。
- **`--max-images N`：超过就报错退出**，不截断（`Image count N exceeds limit M`）。
- **`--max-cost F`：按 `image.estimated_cost_per_image` × 张数预估，超上限就报错退出。** 预算预检不通过就减少内文图，**不能绕过上限**；`max_cost` 为空时省略该参数。
- 多 provider **顺序 fallback**（`image.providers` 列表依次尝试；单张失败不拖垮整批；也兼容旧的单 provider 写法）。内置 provider：`doubao`、`openai`、`gemini`、`dashscope`、`minimax`、`replicate`、`azure_openai`、`openrouter`、`jimeng`、`sub2api`。

## 9. 占位符与 `imgs/` 分工

写作侧只出 `![类型：描述](placeholder)`。**封面不进正文**：`![封面：…]` 仅用于微信封面上传，替换时**跳过或删除该行**，封面单独存为文章目录根下的 `cover.{ext}`。

**`imgs/` 目录分工（硬）**：

| 位置 | 放什么 |
|---|---|
| 文章目录**根** | `cover.png`（或 jpg/webp）、`article.md`、`article.html`、`article-illustrated.md` |
| `imgs/` 根 | **只放正文引用的最终图** |
| `imgs/prompts/` | 生图 prompt，**每张正文图各一个**，文件名主干与图片一致 |
| `imgs/sources/` | 实证图的来源说明 |
| `imgs/raw/` | 截图与裁切的中间产物 |

**先落 prompt 再生成，不许反过来**——否则出了问题没法复现，想只重跑一张也做不到，只能整批重来（按张计费）。Agent 自己生图时同样要落盘。

**实证说明放 `sources/` 不许放 `prompts/`**：`batch` 是整目录 glob 的，混在里面会照着「来源：https://x.com/…」生成一张**伪造的原帖截图**覆盖掉真的那张——而文章正拿它当证据。脚本已有防线（首行「来源：」或 frontmatter `type: source` 会跳过并告警），但目录放对才是根本。

**`placeholder` 必须替换干净**：正文与 HTML 里都不能留。仅当 `article.html` 里**确实存在** `href="placeholder"` 或 placeholder 被渲染成链接时，才去修 HTML；不要默认每次都执行「修复 HTML」。

**用户供图**（`image_source: user`）：`wxart image-prepare <article_dir> [--cover 02-x.png] [--overwrite]` 会确保 `imgs/` 存在、并生成 `img_analysis.md` 模板（每图含文件名、图片内容、建议章节、推荐用途、图注建议）。**「推荐用途：封面」必须且只能出现 1 次**，其余标「正文」（不加 `--cover` 时取 `imgs/` 里排序第一张）；同步把 `article.yaml` 的 `image_source` 写成 `user`（取值只允许 `generated` / `user`），写稿阶段直接用真实路径、**不再出 placeholder**。顺序：`imgs/` 落图 → 写好 `img_analysis.md` → 再写稿。

## 10. 日志与门禁

**日志**：`{run_dir}/image-generation.log`（正文图批量）、`{run_dir}/cover-generation.log`（封面）。**stdout 与 stderr 一起落盘**：

```bash
wxart image generate {run_dir}/imgs/prompts/01-cover.md -o {run_dir}/cover.png \
  > {run_dir}/cover-generation.log 2>&1
wxart image batch {run_dir}/imgs/prompts/ -o {run_dir}/imgs/ \
  > {run_dir}/image-generation.log 2>&1
```

**为什么必须落盘**：端点忽略比例把封面腰斩、正文图传成了哪个 URL——屏幕上滚过去就没了。实测靠 `cover-generation.log` 里那行「已按 2.35:1 居中裁切: 1024x1024 → 1024x436」才定位到封面为什么难看。

**收尾自检（六条，缺一不可）**：

1. 每张正文图各有一个 `imgs/prompts/*.md`，文件名主干与图片一致（**先落 prompt 再生成**）。
2. 实证图的说明在 `imgs/sources/`，不在 `prompts/`。
3. `article.yaml` 的 `image_medium` 非空，且等于实际用的媒介。
4. 正文图数量与 `image_density` 对得上；删过图位要写明删了哪个、为什么（**每篇最多删 1 个**）。
5. 生成日志已落盘，且看过有没有腰斩告警。
6. `imgs/` 根目录只剩正文引用的图，中间产物已归入 `raw/`；**本篇所有信息位配图共用同一个媒介**，每个图位的形态各自按内容选。

**另外两条硬门禁**：`article.md` 封存后**只读**——配图只能产出独立图片与 `article-illustrated.md`；封面必须在文章目录**根**，不在 `imgs/`（发布脚本的检查项，见 [07-publish.md](07-publish.md)）。

## 11. 失败处置（生图调用）

只要 `image_create.py` **非零退出或 stderr 有 API/网络错误**，就必须分类并摘要报错给用户（含 `❌`、HTTP 状态码、`【配置/认证】`、`网络错误（可重试）`、`[NO_MODEL]`），**不得只说「生图失败」**：

| 类型 | 线索 | 动作 |
|---|---|---|
| 未配置 | 退出码 2、`[NO_MODEL]` | 支持生图且用户明确同意 → 用自身多模态能力按**相同 prompt** 生图，继续替换占位符；否则明确告知不能完成生图，给二选一：配置图片模型后重试，或本篇不配图继续（保留 prompts 并标注无配图） |
| 网络类 | `URLError`、`网络错误（可重试）`、超时、临时 502/503 | **自动再试 1 次**；第二次仍是网络类 → 可降级为 Agent 生图或仅保留 prompts，**须明确告知本次未走专用 API** |
| 配置/凭证类 | 401/403、`【配置/认证】`、配置不完整 | **不要静默降级**。列出须检查项（`config.yaml` 的 `image_model`、密钥、端点、权限），请用户改正后重跑 |
| 业务/参数类 | `【请求参数】`、400、返回体提示 model/size 不支持 | 摘要给用户；可改 model / 尺寸后再试；仍失败则与用户商定是否 Agent 生图 |

**退出码 1 的终点**：只做到「产出 `imgs/prompts/*.md` 与方案」，**不执行**「替换 placeholder」或「修复 HTML」。**例外**：退出码 2 且已获用户同意 Agent 代生图时不受此限，生成后继续走替换。

**必须告知用户当前用的是哪条路**：走脚本 → 「使用 image_create.py 调用专用生图模型（{model}）」；退出码 2 降级 → 「图片模型未配置，本次由当前对话模型直接生图（使用相同配图方案）」；故障降级 → 「本次未走 image_create.py（原因：…）」。**禁止**配置明显错误时静默改用 Agent 却不说明。
