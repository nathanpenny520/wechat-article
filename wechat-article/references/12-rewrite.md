# 多平台改写（小红书 / 抖音）

## 触发与边界

触发语：改写成小红书 / 小红书版 / 抖音版 / 口播稿 / 多平台分发 / 一稿多发 / 平台改写。
**不应被「翻译」「缩写」「换个标题」触发**——那些是单平台编辑动作，走 [04-review.md](04-review.md)。

**内容级真改，不是洗稿、不是翻译、不是缩写、不是换标题。** 重构信息顺序、换开头、改表达、
按平台节奏重组；逐句替换近义词不算改写。

## 1. 定源稿

优先级：用户指定的文件或粘贴内容 > 当前任务的 `{run_dir}/article.md`。
都没有 → 直接问用户「要改写哪篇？给我文件路径或直接粘贴全文」，不要自己挑一篇。

确定后**复制**成 `{run_dir}/source.md`：质量门要拿它当参照，而且它必须与后续版本并存不覆盖。
注意 `{run_dir}/article.md` 已是封存成稿，**改写产物永远不写回它**。

## 2. 定目标平台

用户点名了就用；没点名 → 列出 `{skill_dir}/assets/platforms/` 下的可用平台（当前
`xiaohongshu` 小红书、`douyin` 抖音）问要哪几个，或「全部」。
**默认不要自己加平台**，也不要把公众号当其中一个目标。

## 3. 平台配置

每个平台一个 YAML，位置 `{skill_dir}/assets/platforms/<id>.yaml`，字段全列：

| 字段 | 含义 |
|---|---|
| `id` | 平台标识，也是 `--platform` 名 |
| `label` | 中文名，汇报时用 |
| `output_kind` | 输出体裁：`graphic_text`（图文笔记）/ `oral_script`（口播脚本） |
| `output_filename` | 写到 `{run_dir}/` 下的文件名 |
| `min_chars` / `max_chars` | 正文字数区间；`0` 表示不设限（抖音就是 `0 / 0`） |
| `needs_images` | 是否必须配图 |
| `tag_count` | 标签数量区间 `[min, max]`；`[0, 0]` 表示不要标签 |
| `rewrite_brief` | 该平台的改写要点，**以它为准**，不要凭记忆写平台调性 |

两个平台的实测值：

| | 小红书 | 抖音 |
|---|---|---|
| `output_kind` | `graphic_text` | `oral_script` |
| `output_filename` | `xiaohongshu.md` | `douyin.md` |
| 字数 | 600–1000（含标点） | 不设限（`0 / 0`） |
| 配图 | 必须（`needs_images: true`） | 不需要 |
| 标签 | 3–6 个 | 无 |

## 4. 小红书怎么写

- 调性：种草/分享体，目标是「真人感强、像一篇用心的笔记」。第一人称、口语化、真实细节。
- 结构：**开头 3 行必须抓人**（抛痛点 / 反差 / 结论前置），不铺垫；正文用小标题或 emoji 分点，
  节奏轻快，**一段 1–3 句**；结尾给 **3–6 个话题标签**，形如 `#关键词`，贴合内容与搜索。
- 标题口语化、带钩子，不写书面标题。
- 适度 emoji，**不堆砌**。
- **严禁照搬公众号长句和书面腔**——必须按本调性重写结构与表达。

## 5. 抖音怎么写

- 调性：口播脚本/分镜，目标是「可直接念出来、3 秒留住人」。
- 结构：① **钩子（0–3 秒）**：一句话制造冲突或好奇，给出最反直觉的结论；
  ② 正文口播：口语短句，**每句一个信息点，可念**；③ **每 5–10 秒一个小转折或数据点**；
  ④ 结尾 **CTA**：引导评论 / 关注 / 收藏。
- 输出格式：用「口播：…」与「【画面：…】」**交替排版**，便于直接拍摄。
- **严禁照搬公众号书面表达**，必须改写成可口播的短句。

## 6. 执行顺序（每个平台各走一遍）

1. 读该平台的 `<id>.yaml`，按 `rewrite_brief`、字数区间、标签数、输出格式改写。
2. 过双质量门（第 7 节）。
3. 写到 `{run_dir}/<output_filename>`，**不覆盖 `source.md`、`article.md` 或其它任务的文件**。
4. 多平台时逐个平台独立走 1–3；**每个版本都要与源、与其它平台版本都拉开差异**。

## 7. 双质量门（每个版本都要过）

```bash
wxart score {run_dir}/xiaohongshu.md --json                     # 取 quality_score
wxart similarity {run_dir}/source.md {run_dir}/xiaohongshu.md --json   # 取 max_similarity
```

| 门槛 | 要求 | 不过怎么办 |
|---|---|---|
| 编辑质量 | `quality_score >= 60` | 改这个版本后重跑 |
| 原创度 | `max_similarity <= 0.6` | 重构信息顺序与表达后重跑 |

- 不过就**重写该平台版本，最多 2 次**；2 次仍不过，保留其中最好的一版并**明确说明没过哪个门**。
- `similarity` 算的是字符 **3-gram Jaccard**（先去掉 markdown 标记、空白与标点，只留字母数字与
  中日韩字），`-n` 可改 n-gram 长度；多文件时取两两最大相似度。
- **两个门槛都不是编辑判断的替代品。** `quality_score` 只是机械语言风险分：先自己检查事实、
  平台价值和表达是否自然，再看分数；分够了但读起来仍像公众号，就是没过。

## 8. 原创铁律与人设一致

- 不得把源稿的长句**换个标点**就当新版本。
- 不得复用源稿的**段落顺序**。
- 必须重写成**平台的语体**（公众号长句叙事 ↔ 小红书短句口语 + emoji ↔ 抖音可口播短句）。
- 平台有内容级判重（小红书 180 天去重 + 原创度权重，抖音多重指纹），照搬必被限流。
- 所有平台版本保持**同一个人格**的内核（价值观、视角、专业度），只适配表达方式。
- **作者身份与个人材料边界不因换平台而放宽**：`personal_materials.available=false` 时，
  在小红书和抖音里同样不得编造亲历、朋友同事、采访对话、时间地点与感官场景；
  需要故事开场就换成观察、问题或判断开场（见 [03-write.md](03-write.md)）。

## 9. 小红书的配图

小红书需要图文。**复用当前任务已有的配图**（`{run_dir}/cover.png`、`{run_dir}/imgs/`），
在正文里按 markdown 图片语法引用；源稿没有图时，在**文末注明「需补图」**，
不要用生图命令偷偷补图（生图是费用动作，见 [06-visual.md](06-visual.md)）。

## 10. 新增平台

1. 复制 `{skill_dir}/assets/platforms/xiaohongshu.yaml` 为 `<新id>.yaml`。
2. 填满全部 9 个字段，`output_filename` 不要与既有平台重名。
3. `rewrite_brief` 写成可执行的要点（结构、字数、标签、开头、节奏、禁令），不要只写一句调性。
4. 完稿仍走第 7 节的双质量门，汇报时说明该平台是新增的、门槛沿用同一套阈值。

## 11. 汇报

每个平台版本的产出路径、字数、`quality_score`、`max_similarity` 与重写次数；
小红书版说明配图情况（复用了哪几张，或「需补图」）。**各平台账号发布是用户的手动动作**——
本 skill 只推公众号草稿箱，见 [07-publish.md](07-publish.md)。
