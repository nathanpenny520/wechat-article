# 微信推文制作 · 完整工作流

这份文档是**给人看**的端到端流程。Agent 执行时读的是 `wechat-article/references/` 下的阶段文档。

## 0. 全景

```
                        ┌──────────────────────────────────────────────┐
                        │  用户：「写一篇公众号文章」/「完整制作」/「推到草稿箱」│
                        └───────────────────────┬──────────────────────┘
                                                │
  ① 环境自检  wxart doctor ──────────────────────┴──── 退出码 0 才继续
                                                │
  ② 建任务    wxart run start --mode draft|complete|publish
                                                │     （本篇文章 = 一个任务目录）
  ③ 选题      热点 + 垂类需求 + SEO + 历史去重 → 10 个评分排序选题
                                                │
  ④ 写作      文章任务书 brief.yaml ──→ 主张与证据 claims.yaml
              ──→ 来源账本 sources.yaml ──→ 初稿 draft.md
                                                │
  ⑤ 审稿      五项判断（准确/观点/有用/合声/好读）
              不通过 → 改稿 → 复审（最多两轮）   │
              通过 → review-report.json + 成稿 article.md
                                                │
  ⑥ 封存      wxart run finish ─────────────────┘  ← 此后原始正文只读
                                                │
        ┌───────────────────────────────────────┴───────────────────────┐
        │ 以下三项互相独立，用户要哪项做哪项，都不自动触发                │
        ├───────────────────┬───────────────────┬───────────────────────┤
        │ ⑦ 配图            │ ⑧ 排版            │ ⑨ 发布                │
        │ 封面 + 必要内文图  │ 微信兼容 HTML     │ 需明确授权才推草稿箱   │
        │ 先报数量与费用     │ 跑 validate 门禁  │ 无授权 → 只出本地预览  │
        └───────────────────┴───────────────────┴───────────────────────┘

  随时可用的旁路：⑩ 学习飞轮  ⑪ 数据复盘  ⑫ 多平台改写  ⑬ 业务资料库
```

「完整制作」= ③④⑤⑥ + ⑦ + ⑧ 的连续调用，**不授予发布权限**。

## 1. 环境自检

```bash
wxart doctor
```

退出码 0 继续，1 则本轮只修环境。缺 `style.yaml` 是正常首次状态，不是错误。

## 2. 建立或恢复任务

```bash
# 三种模式
wxart run start --topic "选题，可空" --mode draft    --visual-mode none   # 只出成稿（默认）
wxart run start --topic "选题，可空" --mode complete --visual-mode none   # 成稿 + 配图 + 预览
wxart run start --topic "选题，可空" --mode publish  --visual-mode none   # 用户已明确要发布

# 续做
wxart run list
wxart run resume <run_id>
```

**一篇文章一个任务目录**：`~/.wxarticle/runs/<run_id>/`。进度可恢复，多篇并行不互相覆盖。

记下自检结果：

```bash
wxart run update --patch '{"flags":{"skip_publish":false,"skip_image_gen":false,"use_writer_model":false,"needs_onboard":false,"diagnosed_at":"YYYY-MM-DD"}}'
```

## 3. 选题

用户已经给了选题就记录并跳过。否则（详见 `references/02-topic.md`）：

1. 抓热点：`wxart hotspots --limit 30`
2. 看垂类需求：`wxart search-articles "垂类词" -n 15 -t 2`
3. 看搜索需求：`wxart seo --json 关键词…`
4. 过一遍历史：`~/.wxarticle/history.yaml` 去重
5. 出 10 个选题，按三维打分排序（热度 30% / 相关度 40% / 切入价值 30%，含历史去重扣分）

```bash
wxart run step topic completed
```

> 选题是**唯一**建议在交互模式停下来让用户选的环节。

## 4. 写作

**顺序不可颠倒**（详见 `references/03-write.md`）：

```
brief.yaml（任务书） → claims.yaml（主张与证据） → sources.yaml（来源） → draft.md（初稿）
```

任务书必须先回答：写给谁、他真正的困惑是什么、这篇文章的核心判断是什么、新意在哪、
反方是什么、适用边界在哪、有没有可用的个人材料。

主张与证据要区分四类：`fact`（必须有直接来源）/ `inference`（要标边界）/
`opinion`（作者判断）/ `user_experience`（**只能来自用户本轮提供的材料**）。

然后按 7 个写作框架之一推进（痛点 / 故事 / 清单 / 对比 / 热点解读 / 观点 / 复盘），
在 7 个人格里选一个注入语气，最后写出初稿：

```bash
wxart draft check <draft.md>            # 机械自检：导语、加粗密度、金句、数字覆盖
wxart draft draft <topic-card.md> -o <draft.md>   # 或交给写作模型
wxart llm-write --brief <brief.yaml> --output <draft.md>
```

## 5. 审稿

五项判断，各 1–5 分：**准确 / 观点 / 有用 / 合声 / 好读**。
门槛：**平均 ≥4、单项 ≥3、无阻断问题**。四类阻断直接退回：编造亲历、核心事实无来源、
论点与证据脱节、没有明确结论。

```
wxart score <draft.md> --json                 # 语言风险分（只提示，不决定放行）
写 assessment.yaml                            # 五维评分 + 阻断项 + 决定
wxart content-eval --draft draft.md --final article.md \
      --assessment assessment.yaml --output review-report.json --json
```

决定只有三种：`pass` / `revise`（必须真的改稿再复审，不能只列建议）/ `needs_input`。
**最多两轮。** 只有 `review-report.json` 的 `publishable=true` 时才写 `article.md`。

```bash
wxart run step review completed
```

## 6. 封存

```bash
wxart run finish
```

它把成稿、来源与写作结果写入历史，并**冻结原始正文**。此后：

- 配图只能产出独立图片与 `article-illustrated.md`；
- 排版只能产出 `article.html`；
- 要改内容就新建任务，旧任务不可改。

## 7. 配图（可选，独立）

```bash
wxart image --engine aws styles                     # 看可用形态
wxart image generate <prompt.md> -o cover.png --size 2.35:1
wxart image batch imgs/prompts -o imgs
wxart image check cover.png                         # 尺寸 / 近单色检查
```

规矩（详见 `references/06-visual.md`）：

- **先生成 prompt 再生成图**，不许反过来——否则出问题无法复现，想只重跑一张也做不到。
- 先报**数量与预估费用**；严守 `max_images` 与 `max_cost`。
- 封面必须由脚本生成，不许把素材库的图直接复制成 `cover.png`。
- 图位分两类：信息位（删掉读者看不懂，内容必须逐字取自文章）与节奏位（删掉读者读不下去，不加字）。
- 每篇配图共用**一个手绘媒介**（白板 / 便签 / 终端 / 打印稿批注…），篇间按内容换。
- 缺图片服务时降级为只交付提示词，**正文与 HTML 里不能留 `placeholder`**。

## 8. 排版（可选，独立）

```bash
# 默认引擎：18 套主题 + 微信兼容自动修复
wxart format article.md -t sspai -o article.html
wxart validate article.html          # ← 门禁：必须退出码 0
wxart gallery                        # 并排预览全部主题

# 备选引擎：8 套模版 × 3 配色 + 版式组件
wxart format --engine aws article.md --theme 杂志 --scheme 石青 -o article.html
wxart format --engine aws --list-themes
```

门禁：`article.html` 必须由**当前**正文重新生成；换引擎或换主题后必须重跑 `wxart validate`。
`wxart validate` 有 14 条 ERROR 规则，**它不会自动阻断，必须显式跑并要求退出码 0**。

## 9. 发布（可选，需明确授权）

```bash
wxart run permission publish allow     # ← 用户本轮明确要求发布时才执行
wxart article-init <run_dir> --title "标题" --author "署名" --digest "摘要"
wxart publish check-wechat-env
wxart publish full <run_dir>           # 或 wxart publish --engine wx article.md --cover cover.png
```

发布前四道门禁，缺一不可：

1. `article.html` 存在，且由当前正文生成；
2. 封面在**文章目录根**（`cover.png`），不在 `imgs/` 里；
3. `article.md` 与 `article.html` 都不含 `placeholder`；
4. 用户已明确授权，且元数据（`title`/`author`/`digest`/`content_source`）齐全。

拿到回执后才把 `article.yaml` 的 `publish_completed` 写成 `true`；
否则只能报「草稿已提交，正文配图未完成」。

## 10. 旁路能力

| 能力 | 触发 | 命令 |
|---|---|---|
| 学习飞轮 | 「学习我的修改」 | `wxart learn-edits --draft D --final F` → `--summarize --json` → 更新 `playbook.md` |
| 范文库 | 「导入范文」 | `wxart fetch-article <url> -o x.md` → `wxart exemplar x.md -s 账号名` |
| 学排版 | 「学习排版」 | `wxart learn-theme <url> --name my-theme` |
| 数据复盘 | 「看看文章数据」 | `wxart stats --days 7` |
| 多平台改写 | 「改写成小红书/抖音」 | 改写 → `wxart score` 与 `wxart similarity` 双门 |
| 业务资料库 | 「保存为产品介绍」 | `wxart product-image …`；写业务内容前先读 `~/.wxarticle/products/` |
| 预设包 | 「导入预设」 | `wxart presets <bundle.aws 或 URL>` |

## 11. 失败与恢复

```bash
wxart run step <topic|write|review|visual|publish> failed --error "简短原因"
wxart run resume <run_id>
```

- 内容步骤失败：保留任务，恢复后只重做失败或未完成的步骤。
- 搜索失败：删掉无法核实的数字与引述，可以继续写分析与经验判断。
- 生图失败：保留提示词，不许留 `placeholder`。
- 发布失败：退化为本地预览，不改文章完成状态。
- 正文已封存后配图/发布失败：不影响 `status=completed`。

排障顺序：`wxart doctor` → `wxart env` → 本篇目录的 `<环节>.log` → 对应阶段文档。
