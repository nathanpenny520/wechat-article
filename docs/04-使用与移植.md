## A. 这个技能怎么用

### A1 它在什么情况下会被触发

唯一入口是 [`SKILL.md`](../wechat-article/SKILL.md)，它的 description 划定了触发范围：

- **触发关键词**：公众号、微信推文、微信文章、写公众号、写一篇、草稿箱、微信排版、公众号配图、公众号封面、公众号选题、今天写什么、一条龙、完整制作、一稿多发、公众号数据复盘。
- **负向边界**：只在微信公众号生态内触发。通用文章 / 博客 / 邮件 / 短视频脚本 / 网站 SEO / PPT **不触发**。

所以「帮我写篇公众号文章」会走这条链，「写个周报」「写篇博客」不会。

### A2 你说一句话 → 走哪条路径

| 你会说的话 | 做到哪里就停 | Agent 主要跑的命令 |
|---|---|---|
| 写一篇 / 帮我写篇公众号文章 | 只交付审过的本地成稿，**不生图、不排版、不发布** | `wxart run start --mode draft` → `wxart draft check` → `wxart content-eval` → `wxart run finish` |
| 完整制作 / 一条龙 | 成稿 + 配图 + 本地排版预览（**仍不发布**） | 上面全部，再 `wxart image` → `wxart format` |
| 推到草稿箱 / 发布 | 在完整制作基础上推草稿箱；**不会因此自动生图** | `wxart run permission publish allow` → `wxart article-init` → `wxart publish full <run_dir>` |
| 只要选题 / 今天写什么 / 起标题 | 只出选题与标题候选 | `wxart hotspots --limit 30`、`wxart search-articles "垂类词" -n 15 -t 2`、`wxart seo --json 关键词` |
| 只要排版 / 转 HTML | 只出 `article.html` 并过门禁 | `wxart format <article.md>`（默认 wx 引擎） |
| 换主题 / 看看有哪些主题 | 换默认主题，或换一篇的主题 | `wxart themes`、`wxart gallery`、`wxart format <md> -t <主题名>` |
| 只要封面 / 出张图 | 只出 `cover.png` 或提示词 | `wxart image generate <prompt.md> -o cover.png --size 2.35:1`；没配图片模型时 `wxart cover "6字钩子" "副标题" -o cover.png` |
| 检查这篇 / 审稿 / 校对 | 只出审稿结论，不改内容 | `wxart draft check <draft.md>`、`wxart score <draft.md> --json`、`wxart validate <article.html>` |
| 学习我的修改 | 沉淀成规则，不改你的稿子 | `wxart learn-edits --draft <初稿> --final <你改后的稿>`，再 `wxart learn-edits --summarize --json` |
| 看看文章数据 / 复盘 | 回填数据 + 选题建议 | `wxart stats --days 7` |
| 改写成小红书 / 抖音版 | 出另一个平台的版本 | 改写 → `wxart score <平台稿> --json`、`wxart similarity <源稿> <平台稿> --json` |

「只做某一环」时，缺的前置产物 Agent 会自己补齐，不会顺手把整条链跑完。

### A3 一次典型调用里 Agent 会做什么

一篇文章 = 一个任务目录 `~/.wxarticle/runs/<run_id>/`，两个引擎共用同一个目录：

```
~/.wxarticle/
├── config.yaml  .env  style.yaml  history.yaml  playbook.md
├── presets/  products/  exemplars/  lessons/  themes/  personas/  venv/
└── runs/<run_id>/                  # run_id 形如 20260715-120000-a1b2c3
    ├── state.yaml                  # 任务真源：只通过 wxart run 读写，不要手改
    ├── brief.yaml  claims.yaml  sources.yaml   # 任务书 / 主张与证据 / 来源账本
    ├── draft.md  assessment.yaml               # 初稿（不是成稿）/ 审稿临时输入
    ├── review-report.json  article.md          # 审稿报告 / 成稿（唯一可发布的正文源头）
    ├── article.yaml  article.html  cover.png  imgs/  article-illustrated.md
    ├── image-prompts.md  preview.html          # 图片提示词 / 本地预览页
    ├── format.log  image-generation.log  publish.log   # 脚本输出一律落盘
    └── source.md  xiaohongshu.md  douyin.md    # 多平台改写产物（可选）
```

七个阶段中间不停：① `wxart doctor` 自检（退出码 0 才继续）；② `wxart run start --topic "…" --mode
draft|complete|publish --visual-mode none` 建任务；③ 选题（热点 + 垂类需求 + SEO + 历史去重，你已给
选题就跳过）；④ 写作（先落盘 `brief.yaml` 与 `claims.yaml`，再写 `draft.md`，素材进 `sources.yaml`）；
⑤ 审稿（五项判断，不通过就改稿复审最多两轮，通过才写 `article.md`）；⑥ `wxart run finish` 封存并
冻结原始正文；⑦ 配图 / 排版 / 发布按需追加，三项互不自动触发。

结尾 Agent 会汇报：标题、成稿路径、带图副本路径、来源数量、图片与预览结果、是否进草稿箱、以及中途的降级。

### A4 命令行怎么用

`{skill_dir}` 是 `wechat-article/` 目录，三种等价写法：`wxart <命令>`（`install.sh` 装到
`~/.local/bin/wxart`）、`python3 {skill_dir}/scripts/wxart.py <命令>`、Windows 用
`py -3 -X utf8 {skill_dir}\scripts\wxart.py <命令>`。`wxart` 不带参数打印按组分好的命令表，
`wxart <命令> --help` 看该命令自己的参数。常用别名：`diagnose`→`doctor`、`image-gen`→`image`、
`publish-wechat`→`publish`。

按组一览（**加粗**的是日常主力）：环境与工作区 `doctor` `init` `env` `home` `migrate` `docs`；选题
`hotspots` `search-articles` `seo`；写作 `draft` `llm-write` `score` `content-eval` `sources`；
排版 `format` `preview` `preview-page` `shot` `deco` `themes` `gallery` `validate`；配图 `image` `chart` `cover` `image-post` `image-prepare`；
发布 `publish` `redraft` `article-init` `getdraft`；学习飞轮 `learn-edits` `learn-theme` `exemplar` `fetch-article`
`build-playbook`；复盘与分发 `stats` `similarity`；业务资料库 `presets` `product-image`；任务与自检
`run` `guard` `validate-env`。

真正要记的十几条：

```bash
wxart doctor                                   # 自检，退出码 0 才继续
wxart env                                      # 打印每一条实际生效的路径与来源
wxart run start --topic "…" --mode draft --visual-mode none
wxart run list / show / resume <run_id>        # 续做先 list 再 resume，不要新建
wxart run finish                               # 封存正文，此后原始正文只读
wxart run permission publish allow             # 发布授权，独立通道
wxart format <article.md> -t <主题名> -o article.html
wxart validate <article.html>                  # 微信兼容性校验
wxart image generate <prompt.md> -o cover.png --size 2.35:1
wxart image check <cover.png>                  # 出图后确定性检查（尺寸 / 近单色）
wxart image batch <prompts_dir> -o <imgs_dir> --skip-existing
wxart cover "6字钩子" "一行副标题" -o cover.png [--accent "#9B2D30"]  # 无生图模型时的本地合成封面
wxart preview-page a.html b.html -o 预览.html   # 375px 手机宽度并排对比多个主题
wxart shot a.html b.html -o 对比.png            # 直接截成 PNG（含横向对照图），用眼睛核对观感
wxart deco a.html -o a-deco.html --skin full   # 加纸纹底 + 花边框（底图自动传到图床换链）
wxart chart spec.yaml -o imgs/01-stars.png     # 把已核实的数字画成正文配图（不编数据）
wxart docs fetch                               # 抓微信官方文档到本地，之后可离线 search/show
wxart article-init <run_dir> --title "…" --author "…" --digest "…"
wxart publish full <run_dir>                   # 传封面 → 传正文图 → 建草稿（一键）
wxart redraft <media_id> <run_dir>             # 只换版式：原地更新已进草稿箱的那条，不新建
wxart stats --days 7
wxart learn-edits --draft <初稿> --final <改后稿>
```

只有三条命令带 `--engine` 开关，默认值按各自长处选：

| 命令 | 默认 | 备选 |
|---|---|---|
| `wxart format` | `wx`：18 套主题、微信兼容自动修复 | `--engine aws`：模版 × 配色 + 版式组件 |
| `wxart image` | `aws`：比例结构化、出图后确定性检查 | `--engine wx`：多 provider fallback、费用硬上限 |
| `wxart publish` | `aws`：多账号、封面裁剪框、自动压缩 | `--engine wx`：单账号快速推草稿 |

### A5 需要你提供什么，什么是可选

只有四项，其中三项有兜底：

| 要提供 | 写到哪 | 不配会怎样 | 影响的能力 |
|---|---|---|---|
| `article_category`、`target_reader`、`default_author` | `~/.wxarticle/config.yaml` | `wxart doctor` 只提示不阻断；写作与审稿没有硬约束，Agent 会在写稿前问你 | 写作 + 审稿 |
| `WRITING_MODEL_API_KEY`（端点写 `config.yaml` 的 `writing_model`） | `~/.wxarticle/.env` | `wxart draft draft` 退出码 2、`wxart llm-write` 退出码 3，由当前 Agent 直接写 | 写作（可选） |
| `IMAGE_MODEL_API_KEY`（端点写 `image_model`） | 同上 | `wxart image generate` 退出码 2，降级为只交提示词；封面可用 `wxart cover` 本地合成 | 封面 / 配图（可选） |
| `WECHAT_1_APPID`、`WECHAT_1_APPSECRET` | 同上 | 发布不可用，只能出本地预览 | **仅**发布 |

- **密钥只写一处**：`~/.wxarticle/.env`。不要写进 `config.yaml`，也不要提交进 git。
- 三项账号配置**不要从历史草稿或对话记忆里反推**，Agent 会问你要当轮答复再写。
- 不配写作 / 画图模型完全可用——Agent 自己写、自己画，流程照走。

## B. 换一个 agent 用，需要二次配置吗

结论先给：**状态与配置是机器级的，同一台机器换 agent 不用重配，只要挂载；换机器要带走 `~/.wxarticle/` 里几个文件；换项目目录什么都不用做。**

### B1 同一台机器换 agent：不用重配，只要挂载

所有状态与配置都在 `~/.wxarticle/`（`$WXARTICLE_HOME` 可改），与 agent 无关。换 Claude Code、
Codex、Cursor、OpenClaw……都只是换一个「能读到 SKILL.md 的入口」。

```bash
cd <技能目录>/wechat-article && bash install.sh    # 幂等，可重复跑
```

它一次挂到这些位置（存在哪个就挂哪个，都是指向技能目录的软链）：

| Agent | 挂载路径 |
|---|---|
| Claude Code | `~/.claude/skills/wechat-article`（可用 `CLAUDE_SKILLS_DIR` 改） |
| 通用 agents 约定 | `~/.agents/skills/wechat-article`（可用 `AGENTS_SKILLS_DIR` 改） |
| Codex | `~/.codex/skills/wechat-article`（检测到 `~/.codex` 时） |
| OpenClaw | `~/.openclaw/skills/wechat-article`（检测到 `~/.openclaw` 时） |

没有 skills 目录约定的 agent（例如 Cursor 走 rules / `AGENTS.md`），把 `SKILL.md` 的绝对路径接进
它的规则文件即可，命令仍通过 `wxart` 调用——状态照样读 `~/.wxarticle/`。

只想挂载、不想动 venv：`bash install.sh --no-venv`；只想建环境、不挂载：`--no-link`；不清断链：
`--no-clean-stale`。手工挂载等价于脚本里那一步：

```bash
ln -sfn "$PWD" ~/.claude/skills/wechat-article
ln -sfn "$PWD" ~/.agents/skills/wechat-article    # ~/.codex、~/.openclaw 同理
```

挂完验证两件事：`wxart env`（看 `skill_root` 与 `state_home`）、`wxart doctor`（退出码 0），然后对新 agent 说「写一篇公众号文章」即可。

### B2 换一台机器：带走什么

**技能目录本身是自包含的**——两套引擎源码、预设源、人格与平台定义都在 `wechat-article/` 里，
`wxart init` 会把预设铺到状态目录。所以最省事就是把技能仓库 `git clone`（或直接拷贝
`wechat-article/` 目录）过去，跑一次 `bash install.sh`。**没有状态文件也能用。**

| 档位 | 带走什么 | 结果 |
|---|---|---|
| 最小可用 | 只要技能目录 | 流程全通；账号配置与历史从零开始，重新填三项即可 |
| 完整迁移 | 技能目录 + `~/.wxarticle/` 的 `config.yaml`、`.env`、`style.yaml`、`presets/`、`products/`、`exemplars/`、`history.yaml`、`playbook.md` | 账号配置、密钥、写作风格、预设与资料库、历史、范文、学到的规则全部延续 |
| 可以不带 | `runs/`（历史任务产物，体积大，要留档再带）、`venv/`（新机器重建）、`corpus/`、`lessons/`、`themes/` | 不影响可用性，按需补带 |

```bash
# 旧机器打包
cd ~/.wxarticle && tar -czf ~/wxarticle-transfer.tar.gz \
  config.yaml .env style.yaml presets products exemplars history.yaml playbook.md

# 新机器还原
git clone <技能仓库地址> wechat_含微信推文撰写skill
cd wechat_含微信推文撰写skill/wechat-article && bash install.sh   # 建 venv、挂载、wxart init
mkdir -p ~/.wxarticle && tar -xzf ~/wxarticle-transfer.tar.gz -C ~/.wxarticle
wxart doctor
```

解包会覆盖安装脚本生成的空模板，这是预期行为。建议**先 install 后解包**：`wxart init` 先建好
目录与软链，再由你带过来的文件覆盖模板。

### B3 同一个 agent 里换项目目录：什么都不用做

状态目录**不随项目走**。在任意项目目录里运行 `wxart`，工作区根会自动出现两个**兼容软链**：

| 工作区里的名字 | 指向 | 作用 |
|---|---|---|
| `.aws-article` | `~/.wxarticle/`（或项目覆盖层 `.wxarticle/`） | 让引擎按 CWD 相对路径读到同一份配置 |
| `aws.env` | `~/.wxarticle/.env` | 让引擎按 CWD 相对路径读到同一份密钥 |

两个都是**别名**：不要往里另存东西，也不要以为那是第二份配置。把它们加进 `.gitignore`
（本仓库已写了 `.aws-article`、`.wxarticle`、`aws.env`、`config.yaml`、`.env`）。

需要「**一个仓库一个公众号**」时才建项目覆盖层：

```bash
mkdir -p <工作区>/.wxarticle                  # 真实目录，不是软链
cp ~/.wxarticle/config.yaml <工作区>/.wxarticle/
wxart init                                    # 把 .aws-article 重新指向这个覆盖层
wxart env                                     # config_dir 一行告诉你当前生效的是哪一份
```

生效规则：**项目覆盖层 > 用户级状态目录**。删掉该目录、重跑 `wxart init` 就回到共享配置。

### B4 完全不想动默认位置：五个环境变量

| 变量 | 默认 | 什么时候用 |
|---|---|---|
| `WXARTICLE_HOME` | `~/.wxarticle` | 状态目录换地方：多套账号隔离、放到大盘、做测试沙盒 |
| `WXARTICLE_WORKSPACE` | 自动探测（向上找真实 `.wxarticle/`、真实 `.aws-article/` 或 `.git`） | 软链建错地方、`drafts_root` 相对路径不对时钉死工作区根 |
| `WXARTICLE_CONFIG_DIR` | 自动（项目覆盖层 > 工作区真实 `.aws-article/` > 状态目录） | 排障时强制指定配置目录，绕过一切自动判断 |
| `WXARTICLE_LEGACY_HOME` | `~/.wewrite` | 旧状态放在别处时给 `wxart migrate` 指路 |
| `WXARTICLE_PYTHON` | 无 | **只被回归测试读**：`bash wechat-article/tests/run.sh` 用哪个解释器 |

另外几个容易混淆的：`WEWRITE_HOME`（旧名，`WXARTICLE_HOME` 没设时仍被沿用）；`WXARTICLE_NO_REEXEC=1`（禁止自动
切到受管 venv，见 B5）；`PYTHON`（`install.sh` 用它挑解释器，如 `PYTHON=/opt/homebrew/bin/python3.12 bash install.sh`）；
`CLAUDE_SKILLS_DIR` / `AGENTS_SKILLS_DIR`（改 `install.sh` 的挂载目标）。

### B5 依赖：为什么需要 Python 3.11+ 与那些包

- **Python 3.11+**：wx 引擎（排版 / 校验 / 评分）要求 3.11+，aws 引擎部分能力 3.10+ 可用。
- **必装**：`PyYAML`（所有引擎读配置与主题的前提）、`markdown` / `beautifulsoup4` / `cssutils` / `Pygments`（排版转换）、`requests`（抓热点、搜索、发布）。
- **可选**：`Pillow`——图片压缩、按比例裁切、封面裁剪框、出图后检查。缺了会跳过这几步，不阻断排版与发布（但大图会被微信拒收，报 `40009`）。

受管 venv 在 `~/.wxarticle/venv`，由 `install.sh` 或 `wxart init` 创建，清单来自
`wechat-article/scripts/requirements.txt`。`wxart` 启动时会做一件事：**受管 venv 存在、且当前
解释器缺依赖时，静默切到 venv 的解释器**（`maybe_reexec_into_venv`）。所以在一个没装依赖的系统
python 下敲 `wxart format` 也能跑通，不需要手动激活 venv。不想用受管 venv：

```bash
bash install.sh --no-venv                                # 1) 压根不建，自己装依赖
pip3 install -r wechat-article/scripts/requirements.txt
export WXARTICLE_NO_REEXEC=1                             # 2) 建了但不想被自动切过去
```

`wxart env` 的 `python` / `venv_python` / `missing_modules` 三行告诉你当前到底在用哪个解释器。

### B6 不需要二次配置的部分

这些都**随技能目录走**，换 agent、换机器都不用重配：预设库（`structures` / `closing-blocks` / `title-styles` /
`cover-styles` / `image-styles` / `sticker-styles` / `components` 七类文本预设 + 排版模版与配色 +
`article.example.yaml`，由 `wxart init` 铺到 `~/.wxarticle/presets/`）、**8 套排版模版**（亲和 / 资讯 /
书卷 / 杂志 / 手账 / 技术 / 活力 / 硬朗，每套 3 档配色）、**18 套排版主题**（`wxart themes` 列出）、
**7 个写作人格**（`midnight-friend`、`warm-editor`、`industry-observer`、`sharp-journalist`、
`cold-analyst`、`humor-storyteller`、`tech-coder`）、**封面与配图形态库**（12 种封面形态 + 8 种正文配图
形态 + 媒介轮换方法）、**平台定义**（小红书 / 抖音两套改写规范），以及 `install.sh` 与 `tests/run.sh`。
唯一跟着机器走的是 `~/.wxarticle/` 里的个人状态，就是 B2 表格里列的那些。

## C. 速查表：我要做 X，该怎么做 / 该说什么

| 我要做的事 | 对 agent 说 | 或直接敲命令 |
|---|---|---|

## D. 常见坑

**1. 报「容器与目标引擎不相容」→ 退出码 4。** `steps` 在两个引擎里同名但语法完全不同（wx：`:::steps` 每行一步；
aws：`:::steps[标题]` 每行「步骤名 | 说明」），`highlight` 在 aws 已废弃。写错引擎不报错、只渲染成别的结构，
所以排版前先扫一遍，报错形如 `[ERROR] 第 12 行 :::steps —— 期望写法：…`。按行号改写或换引擎，确认无碍才加
`--force`；单独查用 `wxart guard containers <article.md> --engine wx|aws`。

**2. 报「产物未通过微信兼容门禁」→ 退出码 5。** 规则共 16 条（14 ERROR + 2 WARN）；aws 引擎按 `generic`
口径判，`div` / `class` / `id` 降级为提示。先 `wxart validate <article.html>` 看具体规则，换主题或修 HTML 后
**整篇重跑排版**，确认无碍才加 `--no-check`；不要在上一版 HTML 上局部改。

**3. 密钥只写一处，别新建真实的 `aws.env`。** `~/.wxarticle/.env` 是唯一真源，工作区的 `aws.env` 是指向它的
软链。自己建一个真实 `aws.env` 会被「原样沿用」，于是出现两份凭据、改了不生效。密钥也不要写进 `config.yaml`。

**4. 报 `workspace.aws_link … 是断链`。** 换过 `WXARTICLE_HOME`、或手工删过旧状态目录之后会出现，
重跑 `wxart init` 即自愈——它会重新指向当前配置目录，且只删失效软链、不动有效链接。

**5. Windows 上 `python3` 会静默打开 Microsoft Store 而不报错。** 用 `py -3 -X utf8`。另外 Windows
上软链可能建不成，此时 `.aws-article` 退化为真实目录，配置仍可用，只是不再与状态目录共享。

**6. 生图退出码 1 与 2 含义不同。** `wxart image` 的 `1` 是硬错误（**包括跑错目录**、找不到配置
文件、API 报错），`2` 才是「图片模型未配置」。把 1 当成 2 去降级，会把真正的环境错误盖过去。

**7. 出图后的检查用 `wxart image check <图>`。** 命令表里另有旧名 `image-check`，实际走不通
（会被上游脚本当成非法子命令拒绝）。`wxart image check` 只做确定性检查，不调 API、不产生费用。

**8. 换引擎、换主题必须整篇重跑排版。** 两个引擎产物形态不同：wx 产出完整 HTML 文档，aws 产出
可直接作为草稿 `content` 的单段 `<section>`。混用两套容器的 HTML 两边都渲染不出来。

**9. 正文封存后不可改写。** `wxart run finish` 之后 `resume` 会报 `immutable`，配图与排版只能产出**新文件**
（`article-illustrated.md`、`article.html`）；要改内容就**新建任务**，不要动旧任务的 `article.md`。

**10. `install.sh -h` 打印的用法行有个笔误。** 它写 `--clean-stale`，实际接受的参数是
**`--no-clean-stale`**；写错会被当成未知参数直接退出（退出码 2）。

排障固定顺序：`wxart doctor` → `wxart env` → 本篇目录下的 `<环节>.log` → 对应的阶段文档。

## 30 秒上手

```bash
cd <技能目录>/wechat-article && bash install.sh   # 建 venv、装 wxart、挂到各 agent、初始化状态目录
wxart doctor                                      # 退出码 0 才继续
# 填 ~/.wxarticle/config.yaml 的 article_category / target_reader / default_author
```

然后对 agent 说一句「**写一篇公众号文章**」。想要图就说「完整制作」，要进草稿箱就说「推到草稿箱」。
换 agent 不用重配；换机器带走 `config.yaml`、`.env` 与几份资料库文件即可。
